# 後続段落のインライン配置物：所属を証明できるものだけ一緒に移動する

2026-10-26。Issue #97。PR #96 マージ後の main `85fe006` を起点とする。評価条件は、実装前の commit `78d511c` で [manifest](../evaluations/paragraph_frame_placed/manifest.json) に固定した。結果は [results.json](../evaluations/paragraph_frame_placed/results.json)。

## 結論

- 後続段落にインライン配置物（InDesign の `/PlacedPDF` アイコンなど）があると、従来は一律に拒否していた（`a following paragraph with an inline placed object cannot move`）。所属を証明できる配置物は、その段落の文字と同じページ上の移動量で一緒に動かすようにした（2章）。
  - 配置物の演算子は書き換えず、`q 1 0 0 1 tx ty cm … Q` で囲む。白塗り・ラスター化・二重描画はしない。
  - 証明できないものは、理由を付けて拒否する。
- 生成した fixture では、移動を伴う長文化・短文化を保存し、保存したPDFだけから元に戻せた。
  - 3件・6手を保存し、6/6 で配置物の監査（移動の検査と保護の検査）が合格した。
  - 元に戻した結果は、3/3 でページが元と同一だった。
  - 共有 Form XObject を描く配置物は、XObject を変えずに、その呼び出しだけが動いた。
- **実PDFでは、従来拒否されていた長文化を、所属を証明して保存できたものはない。** 成功扱いにはしない。
  - 調査した36ページで、後続段落に配置物があるのは府政だより477の p7・p8 の13段落だけだった（1章）。
  - 拒否の内訳（4章）：
    - 12手：その行に段落と一緒に動かない描画がある。すべての「HP」行に、検索欄の枠・検索ボタン（シェーディング）・リンク注釈があり、もう1件は QR コードの画像。
    - 4手：容量（枠の下端）。
    - 1手：移動先で別の描画と重なる。
    - 3手：固定した編集文字列のグリフがフォントにない。
  - 次の障壁：
    - 行の装飾（検索欄・ボタン・リンク注釈）を段落の一部として証明し、注釈の矩形ごと動かすこと。
    - 下に続く別の要素（「問」の行など）を動かすか、枠を広げる承認。
- 実PDFの保存・拒否・安全性・品質・構造・再編集は、従来と同じ（11手保存、20手拒否、1手は実行できず。いずれも同じ手）。違うのは、従来の一律拒否13手の理由が、上の具体的な理由になったことだけ。
- 既存機能：PR #87〜#96 の回帰は 5章。

## 1. 実PDFの拒否の分類（実装前）

`follower_survey.py` で、PR #91〜#96 で使った PDF の36ページ（府政だより477 の全8ページ、pdf.js のテストPDF、Word・LibreOffice の PDF）を調べた。各段落を選んだときに、一緒に動く後続段落に固定の配置物（semantics の `fixed`）があるかどうかを見た。

- 段落の群：1,250。検出できたもの：1,112。
- 自身に配置物がある段落：27（477 の p1・p2・p3・p7・p8）。
- 後続段落に配置物がある段落：**13**（p7 に7、p8 に6）。ほかの文書には一つもない。
- 後続段落の配置物は、すべて `/PlacedPDF`（タグなし）。
  - 12段落では、後続の最後が「HP 検索欄」の行。
  - p8 の2段落では、後続に「日・定・申・所」のアイコンの行がある。

p7 の HP アイコンの描画（ページの内容ストリーム）：

```
1 0.5 0 0 k /GS0 gs
21.26 252.709 12.793 10.077 re f          ← 背景（直前に塗る）
/PlacedPDF /MC7 BDC
q 21.26 252.708 12.793 10.077 re W n       ← q と clip は BDC の内側で開き
BT … <0029>Tj 0.715 0 Td <0031>Tj ET
EMC
Q                                           ← EMC の外で閉じる
BT … ET                                     ← 行の続きの文字
… 検索欄の白い矩形・罫線・シェーディングのボタン・「検索」…（印なし、約100演算子）
```

同じ行の検索欄は、配置物の印の外にある印のない描画で、リンク注釈が重なる。段落との関係を示すのは位置だけである。

## 2. 方式

`prototypes/paragraph_frame/placed_move.py`。後続段落の固定の配置物ごとに、移動する単位を決める。次のすべてを満たすときだけ動かす。

1. **単位**
   - 印の付いた範囲（BDC … EMC）。
   - その直前に塗られ、範囲自身が描くもの・切り抜くものの内側にある塗り（アイコンの背景）。
   - 範囲の中で開いた `q` を EMC の後で閉じる場合（`BDC q … EMC Q`）は、その `Q` まで。
2. **場所**
   - 編集を書き込むのと同じ描画プログラム（ページ、または一つの Form XObject の呼び出し。PR #90 の copy-on-write）にある。
   - テキストオブジェクトの外にあり、直前に未完のパス・clip がない。
3. **後に残す状態がない**：単位の深さで使う演算子は、次だけ。
   - パスの構築と塗り。
   - 自身の BDC/EMC と q/Q。
   - XObject の描画（`Do`）。
   - 色・ExtGState・文字状態・CTM・clip を、後続の描画が読む深さで設定しない。だから `q … Q` で囲んでも位置以外は変わらない。
4. **ほかの印と交差しない**。単位が描く文字は、その段落の固定の文字だけ。
5. **行にほかのものがない**：段落の行の帯（その列の幅）に、段落の文字と単位以外の描画・文字・画像・注釈がない。検索欄が残り、アイコンと文字だけが離れるのを防ぐ。
6. **clip**：受け継ぐ clip は矩形で、移動後の単位を含む。
7. **列と衝突**：
   - 移動後の単位は、その列の承認した枠の高さに収まる。縦にしか動かないので、元から枠の横にはみ出していた分はそのまま。
   - 移動先で、元はなかった保護された描画・ほかの文字と重ならない。

書き込みでは、単位の最初の演算子の前に `q 1 0 0 1 tx ty cm`、最後の演算子の後に `Q` を入れる。`(tx, ty)` は、単位の直前の CTM とページ変換の逆で、段落の文字と同じページ上の移動量を表したもの。

- 配置物の後にあった段落の文字は、その単位の直後に描く。描画順と抽出順は元のまま。
- 描く XObject は変えない。共有 XObject のほかの呼び出しは影響を受けない。
- 構造化された（MCID の）後続段落は、配置物の前後で同じ MCID の範囲を二度書くことになるため、拒否する。編集する段落自身と同じ規則。

保存前の検査（`validate_stage`）は緩めず、移動を別に確かめる。

- 動いた単位の文字：グリフ・原点・字形の枠が、移動量だけ正確にずれている（0.001 pt）。
- 動いた単位の文字の、コード・フォント・大きさ・色・描画モード：移動後の位置で同じ。
- 単位の内側の描画・画像：移動量だけ正確にずれている（0.01 pt）。それ以外の描画・画像・リンク・注釈は不変。
- 枠の外のラスター（MuPDF・Poppler）：マスクに加えるのは、単位の元の位置と移動後の位置だけ。中身は上のベクトルの比較で確かめる。
- 移動先の衝突：新しい文字は、移動した単位の新しい位置と、自分の段落の元の重なりを超えて重ならない。

保存記録（save）に `placed_objects_moved`（元と移動後の枠、移動量、文字数）を加えた。

## 3. 固定した評価

実装前（`78d511c`）に固定した。

- **実PDFの13段落**：
  - 段落自身の配置物を含まない最後の8字以上の連続部分（なければ最長）を選ぶ。
  - 長文化：その後に、段落自身の文字で約1行を足す。
  - 短文化：約1行を除く。
- **生成した fixture 5件**（`tests/test_paragraph_frame_placed_follower.py` と同じ作り方）：
  - F1：長文化・短文化。
  - F2：共有 Form XObject を描く配置物の長文化。
  - F3・F4・F5：行の上の別の塗り、単位の深さの色設定、非矩形の clip。
- **手順**：従来B2（main `85fe006`）と改善後B2で各編集を保存し、保存できたら、保存したPDFだけから元に戻す。拒否はその場で終わり、成功に数えない。
- **測るもの**：
  - 保存・拒否（理由と分類）。
  - 安全性・品質（`indesign_evaluate.audit`）、構造、保存したPDFだけからの再編集。
  - 配置物の監査：移動を承認したものが正確に移動先にあり元の位置に残っていないこと。保護された描画・画像・リンク・注釈が不変であること。
  - 元に戻した結果と元のPDFの比較（`roundtrip_evaluate.compare`）。

評価器の修正（固定後、結果を見る前に気づいたもの。ケース・編集・基準は変えていない）：

- 既存の監査が変化を許す領域を、編集する段落だけから、編集する段落と一緒に動く後続段落にした（それに足した行）。段落だけの領域では、後続段落を動かす保存は、配置物の有無にかかわらず枠の外で不合格になる。元に戻す手にも、最初の手で増えた行を引き継ぐ。
- 戻す手で選択文字列がPDFに見つからないものは、評価を止めずに「実行できず」と記録する。P8-10 の短文化の戻し（先頭が空白の選択文字列）。従来B2でも同じ。
- 既存の監査の `non_text_paint_identical`（非文字の描画がすべて不変）は、承認した移動があれば必ず不合格になる。そのまま不合格として記録し、配置物の監査の2つの検査を別に示す。

- C02（P7-07）：

  - 長文化は容量で拒否した。HP 行の下は「問」の行まで 5.7〜8.6 pt しかなく、1行（13.1 pt）を下げられない。
  - PR #92 で固定した C02 の長文化（末尾に「ぜひご相談ください。」を足して1行増える）は、従来の一律拒否から、HP 行の検索欄による拒否になった（5章）。
- 実装の途中では、C02 の短文化が保存された。アイコンと文字は1行上がり、検索欄は残った（目視）。安全性の検査には違反しないが、行として壊れるため、行の帯の検査（2章の5）を加えた。

### 4.3 次の障壁

1. **行の装飾**：
   - HP 行の検索欄（白い矩形・罫線・シェーディングのボタン・「検索」の文字）は、印のない約100演算子で、リンク注釈が重なる。
   - 段落の一部と言える根拠は位置しかない。
   - 動かすには、行の帯の中で閉じた描画群を段落の装飾として承認する契約と、注釈の `/Rect` を同じ量だけ動かして監査する仕組みが要る。
2. **容量**：
   - InDesign の枠は中身に合わせてあり、HP 行の下はすぐ「問」の行（別の段落群）。
   - 長文化には、下に続く要素も一緒に動かすか、枠を広げる承認が要る。
3. **編集する段落自身の配置物**：
   - p8 の段落は、自身に「日・定・申」などのアイコンがある。
   - その前で行が変わると `an inline placed object would move in the new layout` で拒否される（従来どおり）。
   - 今回の単位の移動は、これにも使える見込みがある。

## 6. 実装の途中で見つけて直したこと

- `store_conditions` で、移動した後続段落の記録の一覧に、新しい「移動した配置物の文字」と同じ名前を使っていた。後続段落の記録を持つ保存が失敗した（focused tests の `test_follower_records_move_with_their_paragraph`）。`d1207db` で直した。評価はこの修正後のコードで行った。
- 移動した配置物の文字は、保存前の書式の検査から除くだけだった。移動後の位置で、コード・フォント・大きさ・色が同じことを確かめるようにした（`d1207db`）。
- 列の判定：段落の枠が配置物の行より上で終わるとき、行の帯の検査が段落の文字の幅だけを見ていた。帯の横の範囲を、同じ列の枠の幅にした。
- 配置物の背景が枠の左に 0.5 pt はみ出すとき、容量の検査が拒否していた。縦にしか動かないので、高さだけを見る（横のはみ出しは元のまま）。

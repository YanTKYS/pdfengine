# 折り返した編集文字列の検索・コピーを実PDFで実測する

2026-11-01。Issue #114。PR #113 マージ後の main `dedf44f` を起点とする。評価条件は、指標の実装前の commit `4d84b98` で [manifest](../evaluations/search_copy/manifest.json) に固定した。結果は [results.json](../evaluations/search_copy/results.json)。

## 結論

- **L2・L6（PR #113 の主要ケース）**：
  - 全文検索：**不合格**。日本語の置換が2行に折り返し、今回使った MuPDF の検索（`search_for`）では、この2件のPDFで改行をまたいで見つからなかった（日本語の折り返し一般で不可能という意味ではない）。
  - 行ごとの検索（各行の部分が、その行で、連続して見つかる）：**合格**。
  - 抽出（MuPDF・Poppler）とコピー相当（置換の字形が描かれた範囲を両方の抽出器で読む）：**合格**。
- **L8**：行ごとの検索・抽出・コピー相当が**不合格**。
  - 原因は、元の文書が「MSIME2012」と「の」の間に置いた**字形の位置の隙間**。両方の抽出器が空白として読み、置換の1行目の部分は検索で見つからない。
  - 元のPDFの同じ字形の間に、同じ隙間がある（`as_in_source`）。編集が作ったものではない。それでも不合格として記録し、合格にしていない。
- 実用成功の判定は変えていない（製品契約の変更は設計判断。判断事項 1）。
  - 新しい指標は `approved_audit` の `quality.search_copy` に並べて記録する。既存の `status` は変えない。
  - そのため L2・L6・L8 の実用成功は、従来どおり「未検証」。
- 既存の検索の判定（`search_mupdf`）には2つの問題がある（判断事項 2）。旧の値は変えずに残し、新しい指標と対応付けた。
  - ページのどこかで見つかれば合格とし、編集した段落にあるかを見ない。
  - 1行の中で見つからない置換を「折り返し」として未検証にする（S-L2）。
- 実クリップボードでの確認はしていない（`clipboard_manual` は null）。「コピー相当」は PDF 抽出による再構成である。
- PR #115 のレビューで、評価器の測定誤り2つを直した（6章）。再測定で主な指標は11件とも変わらなかった。S-L4 の「元と同じ」は、根拠が足りないため「由来未確認」になった。

## 1. 指標（`prototypes/paragraph_frame/search_copy.py`）

どの指標も true／false／null（測っていない）で、編集した段落の描かれた行に結び付ける。

| 指標 | 意味 |
|---|---|
| `search_full` | MuPDF の `search_for` で置換全体（空白はそのまま）を検索し、置換が描かれた各行の部分をヒットの矩形が覆う。MuPDF は改行を空白として読むので、英文は行をまたいで見つかることがある。日本語は見つからない。ページの別の場所のヒットは `search_full_hits.elsewhere` に数え、合格にしない |
| `search_per_line` | 置換が複数行に描かれるとき、各行の部分（期待する本文を描かれた改行で分けたもの）を、その行で検索して見つかる。行は連続し、部分も連続する（1行目の部分は行末まで、次の行の部分は行頭から）。1行なら null（`search_full` と同じ指標にしない） |
| `extraction_mupdf` / `extraction_poppler` | 段落の各行を1行ずつ抽出し、改行を段落のつなぎ（つなぎなし、または段落にある空白1つ）として読んだものが、期待する段落と一致する。段落の前後の見えない空白のほかは何も正規化しない。空白だけの違いは `whitespace_only`、元のPDFでも同じ違いは `as_in_source` として別に示す（どちらも不合格のまま。`as_in_source` の条件は下記） |
| `copy_equivalent` | 置換の字形が描かれた範囲（各行のその字形だけ）を、MuPDF と Poppler の両方で読むと置換になる。PDF 抽出によるコピーの再構成であり、クリップボードではない |
| `clipboard_manual` | 実クリップボードでの確認。手で行ったときだけ値を入れる。今回は null |

- 失敗の理由：描かれた行が期待する本文と違えば、その位置と字を `reason` に示す。
  - 期待する本文が終わった後に、空白でない字が枠の中に描かれていれば、すべての指標を不合格にする（`drawn but not expected`）。
  - 枠の外の字（同じ行にあっても）は段落の字として数えない。
- `gaps`：置換の中で抽出器が空白として読む位置の隙間。前後の字形と、その間に描かれた空白が、元のPDFと同じ位置にあれば `from_source`。
- `as_in_source`：true か null（「由来未確認」、`as_in_source_note`）。
  - true になるのは、編集後の違いのそれぞれが、元のPDFの違いと対応するときだけ。対応とは、違いの種類と文字が同じで、前後の保持された字形（字と描かれた位置）が同じことをいう。
  - 失敗の分類（空白だけ、など）が同じでも、場所・文字・字形の位置が違えば null とし、元のPDF由来とは言わない。
  - 行ごとの検索の部分：見つからない理由が `gaps` の隙間だけで、そのすべてが `from_source` のときに true。

## 5. 判断事項

1. **実用成功にどの検索を求めるか**（製品契約。このPRでは変えていない）
   - 日本語の置換が折り返すと、今回使った MuPDF の検索器では、対象のPDFで全文検索が成立しなかった（改行をまたいで日本語を見つけない）。日本語の折り返し一般で不可能とは言わない。
   - 代替案：
     - (a) 現状（全文検索の確認が必要。折り返した日本語の置換は未検証のまま）。
     - (b) 行ごとの検索・抽出（MuPDF・Poppler）・コピー相当がすべて true なら、「編集箇所の検索・抽出を検証済み」とする。
     - (c) (b) に加え、実クリップボードの確認を求める。
   - (b) なら L2・L6 が実用成功、L8 は失敗（元の隙間）になる。
   - 設計者の方向（PR #115 のレビュー）：(b) を採る方向。実装は、別の変更で行う。
     - `search_full=false` は記録し続け、全文検索ができるとは表示しない。
     - 既存の実用成功の条件（安全・配置・承認）は引き続き必要。
     - 実クリップボードは独立の null のまま。
2. **既存の `search_mupdf` の測定**（測定誤りの修正の候補。今回は変えていない）
   - ページのどこで見つかっても true になる。
   - 1行の中で見つからない置換を、折り返しとして null（未検証）にする。S-L2 は1行で、元の隙間のため見つからない。新しい指標では false。
   - 直すと S-L2 の既存の判定が「未検証」から「不合格」に変わり、基準の更新が必要になる。
   - 後で測定誤りとして直してよい（レビュー）。そのときは、このPRの新しい指標とは分け、旧結果との比較と理由を残す。
3. **元のPDF由来の隙間**（L8・S-L2）
   - 編集で隙間を消す（字形の位置を詰める）のは、変えていない字形の位置を変えることになる。忠実編集の契約に触れるので、行っていない。
   - 検索の失敗は、元の文書と同じ挙動として記録した。厳密な検索の失敗は、今後も報告し続ける。

## 6. レビュー対応（PR #115、評価器の測定誤りの修正）

製品契約・成功基準は変えていない。固定した結果の値は、再測定で変わったものだけを置き換え、修正前の値をここに残す。

1. **`align()` が期待する本文の後に描かれた字を見ていなかった**
   - 修正前は、期待する本文が終わるとループを抜け、残りの描かれた字を確かめなかった（期待 `ABC`、描画 `ABC余計` でも整列できた）。
   - 修正後は、残りに空白でない字があれば整列を拒否し、すべての指標を不合格にして `reason` に示す。
   - 実PDF 11件への影響：なし（どの段落も、枠の中で期待する本文の後に字はなかった）。
2. **`as_in_source` が失敗の分類だけで「元と同じ」としていた**
   - 修正前：抽出は「元のPDFでも不合格で、`whitespace_only` が同じ」なら true。違う場所の隙間でも true になった。行ごとの検索の部分は「元のページでその部分が見つからない」なら true で、置換の新しい本文では、ほぼいつも true になった。
   - 修正後：対応が示せるときだけ true（1章）。示せなければ null（由来未確認）。
   - 実PDFへの影響（`as_in_source`）：

| ケース | 指標 | 修正前 | 修正後 | 理由 |
|---|---|---|---|---|
| S-L4 | 抽出 MuPDF・Poppler | true | **null（由来未確認）** | 違いは2つ（「e」と「は」の間、「h」と「で」の間）。後者は編集した行にあり、編集で字形が 424.0 から 431.9 に動いた。同じ種類の隙間だが、元の位置の字形の間ではない |
| L8・S-L1・S-L2 | 抽出 | true | true | どの違いも、元のPDFの同じ位置の同じ字形の間の同じ空白 |
| L8 | 行ごとの検索（1行目） | true | true | 隙間「2の」が `from_source` |

   - 主な指標（全文検索・行ごとの検索・抽出・コピー相当）は、11件とも変わらない。

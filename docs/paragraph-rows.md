# 段落・行構造の推定：移動した行の再open（R13）と脚注のぶら下げ字下げ（S2）

2026-10-31。Issue #110（#107 の設計の第2段階）。PR #109 マージ後の main `42f6593` を起点とする。評価条件は、実装前の commit `8586aa0` で [manifest](../evaluations/paragraph_rows/manifest.json) に固定した。結果は [results.json](../evaluations/paragraph_rows/results.json)。

## 結論

- **R13（達成）**：保存したPDFだけから、増えた文字を段落として選び直し、編集・元に戻すことができる。
  - 動かした行（`D-26`・`D-27`）は、新しい本文の行と1つの段落群に結合しない。保存した記録（PieceInfo）の「移動した行」を観察の境界にした。
  - 連鎖の承認で動かした行は、元に戻す編集でも連鎖の候補として示し、id の承認を求める（従来は後続段落として承認なしで戻った）。
  - 承認して元に戻すと、ページの全字形 4,038 が元の位置に戻る（最大 0.00006 pt。従来は 8字形が 0.13 pt ずれた）。画素（72・150 dpi）・リンク・構造も元と同一。
  - 原因：混在した書体の行（小さいラベル＋名前）の大きさ・基準線を字形の中央値で測るため、文字が変わると行の値が変わる。これが誤結合・誤分割・承認の非対称・0.13 pt のずれのもと（1.1）。
- **S2（達成）**：脚注の番号・本文・続く行のぶら下げ字下げを推定する。続く行・増える行は本文の位置（x 73.8）から、行送り 13.8 pt で並ぶ（従来は x 56.8・15 pt）。
  - 脚注の2行目は段落の行になり、編集で下の行を動かさない（忠実編集）。既存の監査も安全性・品質とも合格するようになった。
  - 追加の正例 X1（同じ生成器の脚注5）も同じく改善。負例 4件（表の列をまたぐ行、1行ずつの注記、番号付きの見出し、凡例）は段落群が変わらない。
  - 実PDF 10文書（各8ページまで）の段落群 1,999 のうち、変わったのは S2 と X1 の2群だけ。
- 共通のコード（`auto_detect.observe`・`detect`、`auto_conditions`、`auto_restore`、`auto_writer`）の変更で、PDF・文字列・座標・ページのハードコードはない。タグ・MCID・Form の拒否は変えていない。PieceInfo の検証も同じ。
- 判断事項（6章）：承認しない元に戻す編集で行が下に残ること、1行だけのラベル付き段落、ぶら下げで結合した行を推定の承認で組み直すこと、基準の更新（S2 の改善の2記録）、既存の評価器の場所の探し方。
- 既存機能：`eval_hub` の関連の段階で 864記録を基準と比べ、違いは連鎖の評価の S2 の2記録（改善）だけ（4章）。

5. 連鎖として戻す移動量が、4 と同じ理由で −20.516 pt になった（下へは +20.386 pt）。

ラベル（番号・記号）で始まり、ラベルの後の本文の x と次の行の x がそろう行を、実PDF 10文書（各8ページまで）で探した（`rows_evaluate` の追加ケースの根拠）。

## 2. 方式

### 2.1 移動した行の記録を、観察の境界にする（R13）

- 編集で動かした行は、移動前の観察と移動量を PieceInfo に記録している（PR #97〜#106）。この記録に、**連鎖の要素として承認で動いたこと**（`as: 'chain'`）を加えた。
- 再open で記録が成り立つ（字形が記録の位置に 0.01 pt で描かれている）とき、その行は記録を持ったまま観察に入る（`moved`・`moved_as`）。
- `observe`：記録から来た行は、同じ記録の行とだけまとめる。新しい本文の行と結合しない。
- `detect`：連鎖の要素として動いた行は、編集する段落の後続段落にしない。動かすには、次の編集でも連鎖の候補として示し、id の承認を求める。承認しなければ動かない（元に戻す編集では、行は下に残る）。
- 元に戻すとき、記録した段落の下にあった行は、記録したときの位置より上には戻さない（`follower_shift` を連鎖にも使う。記録した配置がある段落で、下の行が移動の記録を持つときだけ）。
- 記録した配置の置き方：1行目に残る字形の、記録した位置からの移動量がそろっていれば、それを段落の移動とする（中央値の基準線の差を使わない）。
- 移動した字形の照合は、位置を 0.002 pt 以内で1つずつ対応させる（丸めの境界の問題を除く。明白なバグ修正）。

### 2.2 ぶら下げ字下げ（S2）

次の証拠がすべてそろうとき、1行目と次の行を1つの段落とし、続く行の開始位置をラベルの後の本文の x とする（`_label`・`_hanging`）。

1. 1行目がラベルで始まる：数字（1〜3桁）・英字1字・漢数字・ローマ数字（括弧や `.`・`、`・`：` などの区切り付き）、丸数字、`注n`、参照記号（`*`・`※`・`†`・`‡`・`§`）。
2. ラベルと本文が離れている：12 pt のようなすき間（0.3 em 超）、空白、区切り文字、または記号のラベル。
3. 1行目のほかの字形の間に 0.5 em を超えるすき間がない（段の間をまたいで読まれた行を除く。N1）。
4. 次の行の x がラベルの後の本文の x に 0.2 em 以内でそろう。ラベルの x からは 0.5 em 以上右。
5. 同じ大きさ、同じ書体と色を共有する、行送りが 2.25 em 未満。
6. 1行目が段の右端近く（周りの同じ大きさの行の右端から 2 em 以内）まで達する（折り返した行。見出しのように短い行は除く）。

- ラベルの x に戻った行は、次の項目（次の脚注）として新しい段落にする。
- タグ付きの構造要素の中の行には使わない（構造がまとまりを決める）。
- 字下げで行を結合したとき、提案は次を示す（PR #111 のレビュー）。
  - `evidence.inferred.hanging`：ラベル、1行目の x と字下げの x、結合した元の行（全文・x・基準線）、証拠（`basis`）、組み直した後の各行（全文・開始 x・基準線、`proposed`）。
  - `required_approval` に「字下げで段落に結合した行を組み直す（元の行数、提案の行数）」。`evidence.confidence.paragraph` と警告にも字下げの結合を書く。
  - 段落の推定の承認（`acknowledge_inference`）は、この表示を承認することになる。別の論理段落・行の装飾・後続の要素を動かすときは、従来どおり id の承認が必要。
- 1行だけのラベル付きの段落は、字下げの位置を `evidence.inferred.hanging_candidate` と警告で示し、**適用しない**（続く行がないので確かめられない。増える行は1行目の x から始まる。判断事項 2）。

ハードコードはない：PDF・文字列・座標・ページを使わない。

## 3. 評価

## 6. 判断事項

PR #111 のレビュー（設計側）の推奨：1・2 は現状を維持、3 は条件付きで現状を認める、4 は製品方針の承認後に差分理由付きで更新、5 はブロッカーとしない。3 の条件（編集される行の全文・範囲・レイアウトを提案に明示する）は `018a88f` 以降の `evidence.inferred.hanging` で満たす（2.2）。以下は PR 作成時の記録。

1. **元に戻す編集で、連鎖として動かした行を戻さないとき**（R13）。改善後B2は、承認しない保存を受け付け、行は下に残る（すき間）。固定時の期待は「拒否」だった。
   - 代替案：(a) 現状（承認外は動かない。縮める編集は単独でできる）、(b) 戻す承認がなければ拒否（すき間を残さない。縮める編集が承認なしにはできなくなる）、(c) 戻す候補を提案の既定の選択として示す（UI の課題）。
   - 影響：R13 の承認しない元に戻す編集の結果だけ。承認した場合はどれも同じ（元と同一）。
2. **1行だけのラベル付きの段落**（続く行がない脚注・注記）。改善後B2は字下げの位置を候補と警告で示し、適用しない（増える行は1行目の x から）。
   - 代替案：(a) 現状、(b) ラベルの後の x を続く行の x として使う（証拠は1行だけ）、(c) 拒否して字下げの承認を求める（従来保存できた編集を拒否にする。製品契約の変更）。
3. **ぶら下げ字下げで結合した行は、編集する段落の行として組み直される**（S2・X1）。従来は別の段落で、動かすには連鎖の id の承認が必要だった。改善後は段落の推定（`acknowledge_inference`）の範囲で組み直す。承認なしで動く範囲を広げたとも読めるので、判断を求める。
   - 推定は観察した6つの証拠（2.2）がすべてそろうときだけ。負例（N1〜N4、fixture の5件）では結合しない。
   - 代替案：(a) 現状、(b) ぶら下げで結合した段落では、続く行の組み直しに別の明示承認を求める（段落の推定の承認と分ける）。
4. **評価器の測定の修正**（`rows_evaluate.py`、凍結 `8586aa0` の後、記録として残す実行の前）。
   - `moved_apart`：動かした要素の名前（保存記録の、要素の行を連結した文字列）を、段落群の行ごとの文字列と比べていたので一致せず、従来B2の誤結合を見逃していた（途中で止めた最初の従来B2の実行で R13 が「合格」）。段落群の行を連結した文字列に要素の名前が含まれるかで判定するようにした。

   - どちらも測定誤りの修正で、期待は変えていない。
5. 既存テスト・固定評価の期待の変更：なし。

6. **基準（`baseline.json`）の更新**：連鎖の評価の S2 の2記録が変わった（レイアウト調整 → 忠実編集、既存監査の安全性 不合格 → 合格）。固定した評価の合否が変わるので、基準は更新していない。承認されたら `eval_hub baseline --root tmp/hub/i110 --reason ... --design-decision` で置き換える。

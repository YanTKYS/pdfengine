# 明示承認付きのレイアウト調整（第1段階）：背景パネルの縦方向の伸長

2026-11-01。Issue #112。PR #111 マージ後の main `bed99db` を起点とする。評価条件は、実装前の commit `e42e39c` で [manifest](../evaluations/paragraph_panel/manifest.json) に固定した。結果は [results.json](../evaluations/paragraph_panel/results.json)。

## 結論

- **実PDFで、背景パネルのために拒否されていた長文化を、変更IDへの明示承認で保存できた（主要目標）。**
  - 対象は LibreOffice の文書で、図の説明が画像の下の白い矩形に入っているもの。L2（主）、L6・L8（追加）。
  - パネルは下端だけを、増えた1行分（12 pt）伸ばす。上端・左右・色・描画順・演算子は変えない。
  - 承認なしでは従来どおり拒否し、何も書かない。
- 承認した変更の監査で、次を合格とした。
  - パネルの図形が承認どおり変わっていること。
  - 承認外の図形・字形・画像・注釈と、帯の外の画素が不変であること。
  - 抽出（MuPDF・Poppler）、大きさ・色、構造、リンク。
- **検索は未検証**：置換が2行に折り返すため、PR #109 の規則で未検証とした。そのため長文化した手の実用成功は「未検証」で、成功に数えていない（判断事項 2）。
- 保存したPDFだけから、次ができた。
  - 再編集：記録の照合で「承認どおり描かれている」。
  - 元に戻す編集：パネルを戻す ID を承認して保存。字形・画素・図形が元と同一。復元 3/3。
  - さらに長くする編集：新しい ID で改めて承認を求める。
- Word のテキストボックス（W1・W2）は拒否のまま。本文がボックスの内側でクリップされ、クリップの延長は今回の許可の外（判断事項 1）。
- PR #106 の背景の拒否 9件は救えない（角丸のパスが5件、外側の背景の中で空きがないものが4件）。負例 N22・N07 は拒否のまま。
- 見た目に現れる色付きの矩形パネルの実例は、手元の文書になかった。塗りのみ・塗り＋輪郭・`B` の正例と、非矩形・共有・クリップ・衝突・背後の画像・証明できない背景・透明・承認の使い回し・改ざん（保存前後の比較と、改ざんしたPDF単体の再open）の負例は、fixture で確かめた（22件）。fixture の成功は実PDFの成功に数えない。
- 既存機能：`eval_hub` の関連の段階で 864記録を比べ、違いは PR #111 の S2 の2記録（承認済み。基準を理由付きで更新）だけ。

## 1. 対象の調査（実装前）

### 1.1 背景のために拒否された既存の例（PR #106 の R07〜R25）

| ケース | 背景 | パネルだけの伸長で救えるか |
|---|---|---|
| R07・R08（477 p3）、R09（p3）、R11（p4）、R21（p6） | 角を丸めたパス（`c` の曲線を含む） | 救えない。矩形ではない（今回の対象外） |

### 1.2 実PDFの調査

実PDF 10文書（各8ページまで）で、「1つの矩形（`re` と塗り）の中にあり、あと1行増えるとはみ出し、矩形の下に1行以上の空きがある段落」を探した（manifest の `survey`）。

| 生成器 | 見つかった例 | 描き方 | 結論 |
|---|---|---|---|
| LibreOffice（lo_newfeatures_ja） | 図の説明 8 | 画像の下の白い矩形 1つ（`re f*`）。クリップなし | **対象**。L2（主）、L6・L8（追加） |
| Microsoft Word（通知文・指針） | 連絡先のテキストボックス 2 | 塗り（`re f*`）と輪郭（`re S`）が別の演算子。本文はボックスの内側の矩形でクリップ（`re W* n`） | **拒否のまま**。パネルを伸ばしても増えた行はクリップの外で描かれない（判断事項 1） |
| ほか（pdf.js の英文など） | 灰色の見出し帯など | 長文化しても行が増えない、画像に当たるなど | 対象外 |

LibreOffice の例は白い矩形で、白い紙の上では延長が見た目に現れない。見た目に現れる色付きの矩形パネルで、安全に伸ばせる実例は手元の文書には見つからなかった（fixture で確かめた。4章）。

## 2. 方式

`prototypes/paragraph_frame/panel.py`。段落の枠の下端を決めているのが、段落を囲むパネル（またはその輪郭の下辺）のとき、そのパネルの延長を候補として示す。

### 2.1 候補になる条件

- 段落の文字を描くのと同じページの内容ストリームで、1つの `re` だけからなるパスを塗る演算子（`f`・`f*`・`F`、輪郭付きの `B`・`B*`）が 1つ。同じ矩形を描く輪郭（`re` と `S`）はパネルに属する。
  - 曲線や別の部分パスを含むパス、同じ矩形の2つ目の塗り、パターン・色空間、透明（`ca`・`CA`）、ブレンド・ソフトマスク、回転・傾きのある CTM、テキストオブジェクトの中、Form XObject は拒否（理由を `evidence.panels.unavailable` に示す）。
- パネルは段落の文字より前に描かれる（文字の下にある）。
- 延長したパネルは、パネル自身のクリップの中に収まる。
- 段落の文字のクリップが枠を止めているときは、クリップを延長しない（Word のテキストボックス）。
- 延長量は段落の最後の行の増分（パネルの下の余白を保つ最小値）。上端・左右・色・線の太さと種類・描画順・演算子は変えない。
- 延長で加わる帯（下端より下、輪郭の幅を含む）に、文字・図形・画像・注釈がない。ページの外に出ない。
- 延長したパネル全体を含む背景は、次の条件をすべて満たすときだけ許す（PR #113 のレビュー）。延長が覆うのは、もともとパネルの下に見えていたのと同じ単色の塗りだけになる。
  - 1つの不透明な矩形を、デバイス色で塗ったもの。
  - 輪郭がない。
  - パネルより前（下）に描かれている。
- 画像（写真・背景画像）や、それ以外の図形（多角形・曲線・複数の部分パスなど）が延長の背後にあれば、隠すことになるので拒否する（理由を示す）。

### 2.2 提案・承認・保存

- 提案の `evidence.panels.candidates` に示す内容：
  - 変更 ID（`panel-extension-…`）
  - 元の矩形と延長後の矩形（ページ座標）、延長量、変える辺（下端だけ）
  - 書き換える演算子（位置と元のバイト列）と描き方（塗りの色、輪郭の色と太さ）
  - 加わる帯、理由、承認しないときの振る舞い（拒否）
- ID は、元PDFの digest、選択文字列・置換・出現番号、内容ストリームの digest、演算子のバイト列、矩形と延長量から作る。別の PDF・別の編集・別の延長では ID が変わり、承認にならない。
- `propose(..., panels=[id])`（CLI は `--panel`）で ID を承認したときだけ伸ばす。
  - `acknowledge_inference`、連鎖の ID、以前の編集の承認では伸びない。
  - 承認していなければ、従来どおり拒否（容量）し、何も書かない。
- 保存では、`re` の4つの数値を書き換える（下辺だけが動く）。
- 保存前の検査（`validate_stage`）：
  - パネルの図形は「延長後の矩形」として照合する（0.01 pt）。ほかの図形・画像・リンク・注釈は不変。
  - 画素の比較から外すのは、加わる帯だけ。
- 保存記録 `panels_extended`。段落の記録（PieceInfo）に、元の矩形・延長後の矩形・承認を残す。

### 2.3 保存したPDFだけからの再編集

- 保存時に、延長後の `re` 演算子（書き換えた文字列）、塗りの演算子、描き方（塗りの色、輪郭の色と太さ）を段落の記録に残す。
- 再open すると、記録した延長が「承認どおり描かれている」かを照合して、`evidence.conditions.panels` に示す（PR #113 のレビュー）。照合する内容：
  - 記録した矩形の塗りが1つと、その輪郭がある。
  - 演算子の文字列・塗りの演算子・色・太さが記録と同じ。
  - 不透明で、段落の文字より前に描かれている。
- 1つでも違えば、段落の記録を適用しない（stale。理由を示す）。そこから後の編集の条件（承認した下端、パネルを戻す候補）も出さない。
- さらに長くする編集では、新しい延長を新しい ID で示し、改めて承認を求める。
- 短くする編集では、パネルを戻す候補（延長前の下端より上には戻さない）を ID で示す。承認しなければパネルはそのまま（下に余白が残る）。承認すれば元の矩形に戻る。

### 2.4 監査（`approved_audit`）

- 変更の種類 `panel` を加えた（従来は「未対応の種類」で `unverified`）。
- 保存後の図形が「元の図形のうち、承認したパネルの矩形だけを延長したもの」と一致する（0.02 pt）ことを確かめる。
  - ほかの図形が1つでも違えば不合格。
  - 画素の比較から外すのは、加わる帯だけ。
- 承認の照合：承認した ID がこの提案の候補であること、承認なしの延長がないこと、承認したのに延びていないことがないこと。
- 既存の監査（`indesign_evaluate.audit`）は変えず、並べて記録する。

## 6. 判断事項

1. **Word のテキストボックス（本文のクリップ）**（W1・W2）。Issue #118 で選択肢 (b) に近い形（クリップとパネルを、それぞれの ID の承認で一緒に伸ばす）を実装した（`docs/paragraph-clip.md`）。以下は Issue #112 時点の記録。
   - Word は本文をボックスの内側の矩形でクリップする。パネルと輪郭だけを伸ばしても、増えた行はクリップの外で描かれない。
   - Issue #112 が許す変更は「矩形の塗りとその輪郭」で、クリップは含まれない。そのため候補を出さず、理由を示して拒否のままにした。
   - 代替案：
     - (a) 現状。
     - (b) 同じボックスの内側のクリップ（同じボックスに属することを、位置と演算子の並びで立証できるもの）を、同じ延長 ID でパネルと一緒に伸ばす。
   - (b) を認めれば、W1・W2 の型（Word の連絡先ボックスに1行足す）が編集できる見込み。見た目に現れる枠付きのボックスの実例になる。

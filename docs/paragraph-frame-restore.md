# 装飾・リンクを移動した実PDFを、保存したPDFだけから元に戻す

2026-10-27。Issue #101。PR #100 マージ後の main `cc758cb` を起点とする。評価条件は、実装前の commit `5b7b896` で [manifest](../evaluations/paragraph_frame_restore/manifest.json) に固定した。結果は [results.json](../evaluations/paragraph_frame_restore/results.json)。

## 結論

- PR #100 で保存した実PDFの4件（府政だより477 p7：P7-03・P7-05・P7-06・P7-07 の短文化。HP 行の検索欄・リンクを承認して移動）を、**保存したPDFだけから元に戻せるようになった：1/4 → 4/4**。外部の sidecar は使わない。
- 元に戻した4件は、元のPDFと比べて次のとおり一致した。
  - **字形**：ページの全3,430字形が元の原点にある。最大の差は 0.0002 pt で、許容差 0.01 pt と 0.001 pt のどちらも 4/4。
  - **改行**：編集した段落の元の改行を保っている（4/4）。
  - **描画・画像**：ページのすべての描画と画像が同一（4/4）。
  - **リンク注釈**：8注釈のリンク先と、`/Rect`・`/QuadPoints` が 0.001 pt 以内で同一（4/4）。
  - **意味構造**：元と同じ（4/4）。
  - **画素**（別項目）：MuPDF の 72・150 dpi で、全サンプルが元と同一（4/4）。シェーディングを含む行でも差はなかった。
  - **抽出**：MuPDF は 4/4 で同一。Poppler は 3/4 で、P7-03 だけ段落の間の空行が1行多い（`-layout` の出力と、空白を除いた文字列は同一）。
- 元に戻す操作でも、装飾の候補を示し、その操作の候補を明示的に承認したときだけ移動する。
  - 承認なしの保存は 4/4 で拒否した。
  - 最初の編集の承認を使い回せない。候補の id が違い、使い回すと「この編集の候補ではない」と拒否される（テストで確認）。
- **既存の厳格な監査（`non_text_paint_identical`）は緩めていない。** 元に戻す手は承認した移動を含むので、4/4 とも不合格のまま記録した。移動と保護の監査、リンクの監査は 4/4 で合格。
- 既存機能：PR #87〜#100 の回帰は 4章。

## 1. 原因

保存の前後で、文字列・字形と所属・container・検出した行・推定した枠・保存した条件・装飾の候補を比べた。

- 移動した HP 行の字形は、すべて同じ移動量だけ正確にずれており、MuPDF の行（spans/lines）も保存の前後で同一だった。
- 違いは、行の観察（`pdfeditor` の `_horizontal_lines`）にあった。この観察は、ページ全体の字形を、基準線の近さで**列をまたいで**束ねる。
- HP 行が 13.1 pt 上に移ると、別の列の HP 行の字形（y 617.09 と、0.85 pt の「■」の 617.91）が近くに来る。その結果、束ね方が変わった。

| 例 | 保存したPDFでの行 | 結果 |
|---|---|---|
| P7-03・P7-05 | HP 行の空白（基準線 618.58）が、別の列の「■」の束に入った。HP 段落は「HP」（アイコンの字形だけ）になり、アイコンの印の範囲が段落全体を囲む container と判定された。 | `edited paragraphs lie in different marked-content containers` |
| P7-06 | HP 行・検索文字・「■」が1つの行にまとまった。HP 段落が後続段落と認められず、枠の下端が移動した HP 行の真上（731 pt）で切れた。 | `capacity`（元の行を戻す場所がない） |
| P7-07（C02） | 近くに別の列の基準線がなく、行は元のまま。 | 元に戻せた（PR #100） |

推定した枠を広げたり、container を無視したりはせず、行の観察を元の PDF と同じにする方式を取った。

## 2. 方式

- **保存時**：後続段落を動かす保存（PR #98 の配置物、PR #100 の装飾）は、次の行を、移動した後の位置に平行移動して記録する。
  - 記録する行：元のPDFで観察した行のうち、その保存で動かした字形（後続段落の字形と、グループが運ぶ文字）だけでできているもの。
  - 記録する内容：行の文字・基準線・x・端・枠・大きさと、字形（文字・グリフ・原点）の一覧。
  - 記録先：ページの `/PieceInfo` の既存の項目 `/PdfEngineB2`（PR #93 の条件の記録と同じ JSON）の、`moved` キー。
- **再 open 時**（`auto_detect.page_rows`）：次の両方を満たすときだけ、記録した行を観察した行の代わりに使う。
  - 記録したすべての字形が、記録した原点（0.01 pt）に、同じ文字・グリフでちょうど1つずつ描かれている。
  - その字形を持つ今の行に、ほかの字形がない。
- **使わないもの**：外部 sidecar は使わない。推論だけの提案（`stored_conditions=False`）では記録を使わない。
- **記録の更新**：後の保存は、記録した字形がその時点でちょうど描かれている記録だけを残す。そのうえで、その保存で動かした行の記録を加える。元に戻す保存では、最初の編集の記録は消え、元に戻した位置の記録に置き換わる。
- **承認**：元に戻す編集の装飾の候補は、その編集のもの（id が違う）で、改めて明示的に承認する。最初の承認は使い回せない。
- **リンクの照合**：保存前の検査で、承認したリンクを 0.02 pt で照合するようにした。2回移動したリンクの矩形は、0.01 pt の丸めがどちらにも転ぶ。

## 3. 固定した評価

実装前（`5b7b896`）に固定した。

- **対象**：
  - PR #100 で装飾を承認して保存した実PDFの4件。PR #100 での元に戻す成功は 1/4。
  - 生成した fixture：D1 の長文化・短文化、D2 の長文化。
- **手順**：
  1. 編集し、示された候補を承認して保存する。
  2. 保存したPDFだけを開き、元に戻す編集を提案して、候補を記録する。
  3. 承認せずに保存する（候補が必要な手は拒否されること）。
  4. 示された候補だけを承認して保存する。
- **比べるもの**：各手の保存・拒否、既存の監査、構造、再提案、移動の監査。元に戻した結果と元のPDFの、字形の原点（0.01 pt と 0.001 pt、最大の差）・段落の字形と改行・抽出（MuPDF・Poppler）・検索・描画・画像・リンク・構造。画素は別項目。
- **従来B2**：main `cc758cb`（PR #100 のコード。装飾の承認を持つ）。

固定後、結果を見てから直した評価器の問題（ケース・手順・基準は変えていない）：

- PR #100 のリンクの監査が、0.01 pt の格子に丸めて照合していた。2回移動したリンク（P7-06）が格子の反対側に丸まり、矩形は元と 0.001 pt 以内でも不合格になった。0.01 pt 以内の照合に直し、保存済みの出力で監査だけを計算し直した。変わったのは、P7-06 の元に戻す手の1件だけ。

### 4.2 生成した fixture（3件）

従来・改善後とも 3/3 を元に戻した。字形・改行・抽出・描画・リンク・構造・画素は、すべて元と同一。fixture には列をまたぐ基準線の干渉がないため、今回の改善は実PDFでだけ差が出る。

### 4.3 Poppler の抽出の違い（P7-03）

元に戻した P7-03 の Poppler の抽出（`pdftotext`）は、「…送信ができます。」と「■ 自動車の登録手続き」の間に、空行が1行多い。

- `pdftotext -layout` の出力と、空白を除いた文字列は元と同一。字形の位置と画素も同一。
- 元に戻した段落の文字は内容ストリームに書き直されるため、描画の順序が元と違う。Poppler はその順序から段落の区切りを推定する。
- 不合格として記録した。

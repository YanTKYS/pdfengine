## 1. 開発判断ルール

[docs/development-rules.md](development-rules.md)。要点は `CLAUDE.md` の冒頭。

- 最終目的、既定は忠実編集、編集操作ごとの明示承認によるレイアウト変更（数値は後続の Issue）、禁止事項。
- 成功の階層：①保存、②実用（最重要）、③再編集、④復元（独立の指標）、⑤拒否。忠実編集とレイアウト調整を分けて集計する。未検証・入力不足は合格にしない。
- 委任：実装方式・局所的なリファクタリング・明白なバグ修正・テスト追加・測定不具合の修正は実装側。成功基準・安全な拒否条件・承認範囲・レイアウト変更の種類と量・既存テストの契約・固定評価の期待の実質的な変更は設計判断。
- 既存のテスト・評価器の期待を変えるときは「測定誤りの修正」か「製品契約の変更」かを明記する。
- PR の標準の記載：改善前後、実PDFと fixture の区別、安全性・品質・再編集・復元、実行／未実行のテスト、判断事項。

## 2. 評価の3段階と1つの基準

### 2.1 共通の記録

`eval_records.py`。各評価器の結果（入れ子の形はそれぞれ違う）から、手ごとに1つの記録を作る。

- `outcome`・`reason_class`・`failed`（既存監査の不合格の項目）・`checks`（測った項目だけ）。
- `tiers`：
  - 保存：保存した。
  - 実用：品質（抽出・検索）が合格で、承認外の保護が確かめられた。忠実編集は既存の安全性監査、承認した移動を含む手は移動の監査（PR #98〜#106 の `moves`・`links`・`placement`・`kept`）で確かめる。品質を測っていなければ `null`。
  - 再編集：保存したPDFだけを開き直して編集を続けられた（`continued_editing`）。
  - 復元：元に戻す手の、元のPDFとの比較（字形・画素・抽出がすべて同一）。
  - 拒否。
- `mode`：明示承認した移動（配置物・行の装飾・連鎖の要素）を保存した手は `layout`、そのほかは `faithful`（後続段落の平行移動は忠実編集に含める）。
- スモークでは、実用を新しい監査（`approved_audit`）の合格と品質の合格で決める。

### 2.2 基準と比較

- [evaluations/baseline/baseline.json](../evaluations/baseline/baseline.json)：1行1記録。評価したコード、評価器のファイルのハッシュ（`git hash-object`）、入力PDFのハッシュ、所要時間を持つ。
- 最初の基準は、Issue #105 の節目の全評価（`dd3ea7e`、main `e402b82` とコードは同一）の出力から作った（838記録、13評価）。スモーク（26記録）を新しい評価として足した（`changes.json` の2件目）。
- `compare` は、実行した評価だけを基準と比べる：変わった記録（前・後）、基準にだけある手、今回だけの手、今回は実行していないケース（段階が評価の一部だけを実行したとき）。
- 基準を変えるときは `baseline` で、理由・変わった記録・設計判断の要否を `changes.json` に足す。

## 3. 承認した変更を考慮した監査

`prototypes/paragraph_frame/approved_audit.py`。

### 3.1 契約

- **変更の集合**（`change_set`）：提案（`evidence.observed.lines`・`inferred.frame`・承認した id）と保存記録（`follower_translation`・`placed_objects_moved`・`decorations_moved`・`chain_moved`）から作る。
  - `text`：編集した段落の元の範囲と、承認した枠。
  - `translate`：後続段落（検出から求めた範囲）、配置物、行の装飾、連鎖の要素。それぞれの元の範囲・移動量・承認（`acknowledge_inference`、または装飾・連鎖の id）・リンク。
  - そのほかの種類（段組の流し込みの行ごとの移動、将来の背景の伸長・行間の調整）は「未確認」として示し、合格にしない（`verdict: unverified`）。
- **承認**：保存記録がこの提案のものか（提案と元のPDFのダイジェスト）。動いた装飾・連鎖の要素はすべて承認されていて、承認したものはすべて動き、承認した id はこの提案の候補であること。
- **承認した変更**：平行移動ごとに、範囲の字形（文字・原点 0.01 pt）・図形（種類・色・幅・矩形 0.02 pt）・画像（ダイジェスト・範囲。シェーディングのラスタは色空間と位置 1 pt 以内）が正確に移り、元の位置に何も残らないこと。文字の変更は、新しい文字が承認した枠の中に描かれていること。
- **承認外の保護**：編集した段落・枠・承認した範囲（元と移動先）の外で、インクのある字形・図形・画像・注釈・画素（72・150 dpi）が不変。注釈は辞書（リンク先のページは番号）と位置で対にする（並べ替えに頼らない）。ほかのページとフォームも不変。
- **品質**（安全性と分ける）：MuPDF・Poppler の抽出が元の置換と同じ、検索、編集した段落の文字の大きさ・色が元にあるもの。

### 3.2 既存監査との対照

|---|---|---|---|
| 連鎖 | 不合格 | 合格 | 6 |
| 分離 | 不合格 | 合格 | 11 |
| 行の装飾 | 不合格 | 合格 | 14 |
| 元に戻す | 不合格 | 合格 | 14 |
| 配置物 | 不合格 | 合格 | 6 |

- 既存の安全性の不合格 51件は、すべて承認した移動（`layout`）で、不合格の項目は `non_text_paint_identical`（43）、領域外の画素・字形（17）。既存監査の結果は削除せず、そのまま並べている。
- 品質：既存監査の抽出の不合格 4件（配置物 P8-08・10・11・12）は新しい監査でも不合格。既存の `size_and_colour_kept` の不合格 3件（分離の元に戻す手：元の位置に戻った行が評価器の領域に入る）は、新しい監査（移動した範囲を除き、同じ範囲で比べる）で合格。
- 新しい監査を正式な基準にするか（既存の安全性監査の代わりにするか）は、設計判断として残す（判断事項）。今回は並記にとどめ、既存の結果を合格扱いにしていない。

### 3.3 テスト

`tests/test_approved_audit.py`（12件）：承認した連鎖・分離の移動は合格、移動のない忠実編集は合格。負例：承認外の字形の改変、無関係な図形、リンク先の変更、移動量の違い、承認 id の使い回し（この提案の候補でない id）・承認のない移動・承認したのに動かない・別の提案の保存記録、未確認の変更の種類、編集した段落の大きさ・色の変更。

## 6. 引き継ぐ課題

- **部分埋め込みのフォントの字形の欠落**（スモークで最大の拒否理由。Word 4/4、477 の I3）。代替字形の承認（既存の `substitute`）を利用者にどう見せるかを含め、次の候補。
- **段落推定**：PR #106 の R13（開き直すと段落がまとまり、元に戻せない）、PR #104 の脚注のぶら下げ字下げ。次の Issue。
- **削除の元に戻す**：空の選択で元に戻せない（I2）。挿入位置の示し方の設計が要る。
- **TeX の文書**：行の連結の空白に字形がない（T1）。
- **承認付きレイアウト調整**：背景パネルの伸長・行間・後続要素の再配置。`approved_audit` の変更の種類として足せる形にした（未確認の種類は合格にしない）。
- **重ねた編集の耐久性**、**タグ付きPDF**（構造の監査を先に）、**証明つき書き換えの共通化**。
- **新しい監査を正式な基準にするか**（3.2、判断事項）。
- 評価対象の拡大：ネットワークで取得できない11文書、一太郎・Illustrator。

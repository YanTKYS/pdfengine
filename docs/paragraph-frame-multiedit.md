## 1. PR #94 の経路で残っていたもの

PR #94 の「A を編集 → B を編集 → A を元に戻す」を「元のPDFで B だけを編集」と比べると、元の位置に残った文字は 1,301/1,327 だった。差は C06（58/65）と C09（189/208）に集中していた。

- C06（Word、タグ付き、和文の両端揃え）：B（1行目の短文化）を残したまま A（1行目末から2行目の語順の入れ替え）を戻すと、1行目の「円滑」が B だけの結果より 0.18 pt 右に置かれた。
- C09（LibreOffice、和文と欧文）：A と B が同じ行にあり、A を戻した行の19文字が、B だけの結果と最大 0.07 pt ずれた。

原因は共通していた。**2回目以降の編集は、いま描かれているPDF（それまでの編集の結果）を元の描画として配置していた。** PR #94 の記録は、行の文字列が記録とまったく同じに戻った行にしか使われない。B の変更が残る行は、PR #92 の規則で、B を配置した後の描画を起点に組み直される。B だけの結果は、元の描画を起点に組んだものなので、同じ文字列でも経路によって位置が変わる。同じ理由で、A → B と B → A の結果も一致しなかった（4章）。

## 2. 方式：記録した組版を元の描画として配置する

保存された記録（PR #94）が段落の最初の承認の組版を持つとき、2回目以降の編集は、その組版を元の描画として配置する（`auto_restore.against`、`auto_local.local_layout`）。いまの文字列と記録の文字列の違いを、記録した段落に対する1回の編集とみなし、PR #92 の局所配置の規則をそのまま、記録した文字の位置と字送りに対して適用する。結果は記録と文字列だけで決まり、そこに至った編集・取り消し・順序によらない。

- A → B → A を戻すと、文字列は「元の段落に B だけを適用したもの」になり、B だけの編集と同じ配置になる。
- A → B と B → A は同じ文字列なので、同じ配置になる。
- すべて戻すと、違いがないので、記録した位置にすべての行が戻る（PR #94 と同じ結果）。

### 2.1 記録に加えたもの

PR #94 の記録に、局所配置が元の描画から読む値を加えた。最初の承認で記録し、以後は引き継ぐ。

- 行ごとに、ペンの終わり、最後のインクの終わり、文字サイズ、作者の改行か、行末がハイフンか（`auto_detect.source_rows` と同じ値）。
- 文字ごとに、描かれていた文字サイズ。保存で描き直した文字は、書き込みが小数9桁で書いたサイズとして読まれ、元のサイズとわずかに違う（6章）。
- そのページが新しい文字をどう置いたか：フォントごとのトラッキングの中央値、和文の詰めの中央値、句読点の字送りの中央値（`auto_style.build` が新しい文字に使う値）。最初の編集は元のページのこれらの値で新しい文字を置く。2回目以降の編集のページは、それまでの編集で描き直されているため、値が変わる（C06 では 0.05 pt）。

PR #94 で保存した記録（行の値が4つ）は、PR #94 と同じ方法で使う。

### 2.2 記録と対応する文字

いまの文字列のうち、記録の文字列のまま残っている文字を、最初の編集が残す文字と同じ規則で決める（`auto_restore.retained`）。

- 記録の文字列といまの文字列を文字ごとに対応づける（difflib。同じ長さの候補が複数あれば、記録の側で前にある方。`auto_style.changed_runs` と同じ）。
- 段落が1つのマークド・コンテントのシーケンスなら、最初の編集は「共通の先頭と末尾の間を1つの変更」とする。それに合わせて、両側の変更より短い一致は変更の一部とみなす。新しい語の中の偶然の一致（「array」の「ra」と「range」）や、語順を入れ替えた句（「適切かつ円滑」と「円滑かつ適切」）がこれにあたる。複数のシーケンスを持つ段落（タグ付きの Word）は、最初の編集も文字ごとに対応づけるので、そのまま使う。
- 挿入と削除は、できるだけ右に寄せる（最初の編集は共通の先頭を最も長くとる。「the user」→「the end user」は「end 」の挿入）。
- 記録と同じグリフ（同じ文字、同じフォントプログラムのグリフID、同じリソース）で描く文字だけを対応させる。代替フォントの文字は対応させない。

対応した文字は、記録した原点と字送りを持つ「元の文字」になり、他の文字は新しい文字として、記録したページの値で置く。行の境目の暗黙の空白も記録に合わせる（記録で行末だった空白は暗黙の空白、記録で行の途中だった空白は元の文字）。

### 2.3 描画

配置した行のうち、いまの描画と同じ位置・同じグリフの行は、PR #92 と同じく描画命令ごと残す（記録の位置は小数5桁に丸めてあるので、その範囲でいまの原点と一致する文字はいまの原点を使う）。記録の位置に置いた行が、いまは別の位置に描かれているときは描き直す。描き直す行は、最初に変わる行から最後に変わる行までの1つのまとまりにする（残す行が描き直す行の間に挟まると、内容の順に文字を読む抽出で順序が変わる）。記録で行末の空白にグリフがなかった行は、その空白を描かない（段落の文字列と ActualText には残る）。保存前の検査はすべて同じく適用する。

### 2.4 記録を使わないとき

- 記録がない最初の編集：PR #92 と同じ。
- PR #94 の記録（行の値が4つ）：PR #94 と同じ。
- 段落にインラインの配置物がある：いまの描画を起点に配置する。
- 記録した段落として配置すると、段落か、伸びた分だけ動く後続段落が、承認した編集枠の下に出るとき：いまの描画を起点に配置する（PR #94 と同じ）。たとえば C09 で、短文化 A の後に長文化 B を行い、A を戻すと、文字列は「B だけ」と同じになる。B だけの編集は、後続段落が枠の外に出るため拒否される。一方、A の短文化で空いた行に B が収まっている描画を起点にすれば、保存できる。

## 3. 固定した評価

実装前の main `2e2ec8b` で固定した（`multiedit_evaluate --phase freeze`、`29e0b37`）。

- **対象**：PR #92 の固定評価の段落のうち、同字数・短文化・長文化・折返しを伴う長文化の編集が2つ以上ある段落。それらの編集の組のうち、段落の離れた位置にあり、どちらの順でも適用できるものすべて（12段落、37組）。14組は A と B が同じ行にかかり、23組は別の行。PR #94 の経路（12組）を含む。
- **手順**：組ごとに、A → B → A を戻す → B を戻す（正順）と、B → A → B を戻す（逆順）。各手は、前の手が保存したPDFだけから提案して保存する。拒否された手で系列は終わる。
- **指標**：各手の保存・安全性・品質（`indesign_evaluate.audit`）・意味構造・保存したPDFだけからの再編集（PR #94 と同じ `roundtrip_evaluate.step`）。比較（PyMuPDF と Poppler だけで測る）：
  - `path_b`：A → B → A を戻す を、B だけ（逆順の1手目）と比べる（PR #94 の経路の指標）
  - `path_a`：B → A → B を戻す を、A だけ（正順の1手目）と比べる
  - `order`：A → B を B → A と比べる
  - `full_return`：A → B → A を戻す → B を戻す を、元のPDFと比べる
  - それぞれ、段落の変わらない文字が比べる相手の原点にあるか（0.01 pt）、フォントとサイズ、行数と改行、段落の外の文字、ページの全グリフ、MuPDF・Poppler のページの抽出文字列。

**PR #87 の N4 の再編集。** LibreOffice の和文の段落で、初回の編集は「LibreOffice 4.1.1が8月下旬に」を「LibreOffice 4.1.1は8月末に」にする。再編集は、保存したPDFだけから「8月末に」を「8月下旬に」に戻す。

- 元のPDFは、「8」と「月」の間に、欧文と和文の間の空き（2.4 pt）を入れて描いている。MuPDF も Poppler も、ここを空白として抽出する（「4.1.1 が8 月下旬」）。元のPDFで「8月下旬に」を検索しても見つからない。
- 初回の編集は「が8月下旬」を1つの変更として描き直すので、空きのない「8月」になる。
- 改善後の再編集は、記録した段落への「が」→「は」の1文字の編集として組む。そのため「8月下旬に」は元の文字として、元の位置と字送り（空きを含む）に戻り、抽出は「8 月下旬に」、検索は0件になる。
- PR #87 の監査は、直前のPDF（初回の編集の結果）の抽出から期待する文字列を作る。そのため、コピー・抽出（MuPDF・Poppler）と検索が不合格になる。PR #94 では、直前の描画を起点に組むため「8月」のまま合格していた。
- 元の組版に戻すという点では意図どおりの結果だが、監査の基準は変えず、不合格として記録した。元のPDFと同じ抽出であることは、補助の確認として示す。

**PR #92・#94 が記録した旧来の基準での不合格**：PR #88 の E1・E4・E6 の監査、PR #90 の標本の6件、PR #91 の標本は、すべて同じ結果のまま。

## 6. 実装の途中で見つけて直したこと

評価の段落 C06・C09・C01 で、記録に対する配置の結果を「B だけ」「A だけ」「逆の順序」と1文字ずつ比べ、違いの原因を順に直した。

- **新しい文字を置く値が、いまのページから取られていた（C06、0.01〜0.02 pt）。** 最初の編集は、新しい文字の字送りに、元のページのフォントのトラッキングと和文の詰めの中央値を使う。2回目以降の編集のページは描き直されているため、同じ値にならない（C06 では 0.05 pt）。最初の承認のときの値を記録に残して使う（2.1）。記録で行末だった文字の字送りは、トラッキングを含まない自身の幅（最初の編集でも行末の文字はそう読まれる）。
- **「いま描かれている文字に届く一致だけを残す」規則は順序に依存した（C06、C09）。** PR #94 の、偶然の一致を除く規則（記録の文字列の続きが、まだ描かれている文字に届くか）を最初は使った。しかし語順の入れ替えでは、どの文字がいま描かれているかが編集の順序で変わり、A → B と B → A の結果が違った。文字列と記録だけで決まる規則（両側の変更より短い一致は変更の一部）にした（2.2）。
- **タグ付きの段落では、最初の編集が文字ごとに対応づける（C06）。** 複数のマークド・コンテントのシーケンスを持つ段落では、最初の編集は選択した文字列を文字ごとに対応づけ（`changed_runs` の `aligned`）、語順の入れ替えでも一致した語を元の文字として残す。この場合は短い一致もそのまま使い、同じ長さの候補は記録の側で前にある方を選ぶ（difflib の引数の順序を最初の編集と同じにする）。
- **描き直した文字の文字サイズが、元の文字と別のサイズとして扱われた（C01、0.17 pt）。** 書き込みは `Tf` を小数9桁で書くので、描き直した文字は 9.566900253 として読まれ、元の 9.566900253295898 と一致しない。局所配置は新しい文字の字送りを同じフォント・サイズの文字の中央値から決めるので、どの文字がいま描き直されているか（編集の順序）によって組が分かれた。記録に文字ごとの描画時のサイズを残し、記録の文字にはそのサイズを、新しい文字には前の記録の文字のサイズを使う。
- **記録した段落として置くと、後続段落が枠の外に出る（C09）。** 短文化 A → 長文化 B → A を戻す、の3手目は、文字列が「B だけ」と同じになり、B だけと同じく後続段落が承認した編集枠の外に出て拒否された（改善前は、A で空いた行に収まる描画を起点に組むため保存できた）。段落か後続段落が枠の下に出るときは、いまの描画を起点に組む（2.4）。
- **記録の位置にまだ描かれている行まで描き直していた（PR #92 の固定評価の再編集）。** 記録の位置は小数5桁に丸めている。そのため、まだ記録の位置に描かれている行でも、置いた位置がいまの原点と 1e-9 で一致せず、元に戻す編集で段落全体を描き直していた（PR #92 の部分的な描き直しが失われた。位置は同じ）。記録の丸めの範囲（1e-4 pt）でいまの原点と一致する記録の文字は、いまの原点を使う（PR #94 の行の復元と同じ）。
- **残す行と描き直す行が交互になった（C05・C08）。** 上の修正の後、記録から変わっていない行は描画命令ごと残り、それより前の編集で置いた行は（同じ位置に描かれていても）描き直された。描き直した行はまとめて書き込まれるため、内容の順に文字を読む MuPDF で、描き直した行が段落の別の位置に読まれ、2回目の編集の抽出の検査が不合格になった（評価の13手）。いまの描画と同じ位置・同じグリフの行は残し、描き直す行は、最初に変わる行から最後に変わる行までの1つのまとまりにする（1回の編集の後と同じ形）。
- 新しい文字のグリフを、記録が同じ文字に使ったグリフにする変更も試したが、C01 の違いの原因ではなく（上のサイズの違い）、効果が確かめられないため入れていない。

## 7. 残る課題

1. **記録が使えない場合は経路に依存する。** PR #94 の記録（行の値が4つ）、インラインの配置物がある段落、記録として置くと枠の外に出る場合（C09、2.4）は、いまの描画を起点に組むため、PR #94 までと同じく経路で結果が変わりうる。PR #94 で保存したPDFを再編集しても、記録は最初の承認のまま引き継がれるので、行の値は加わらない。
2. **最初の編集との違いが残りうる点。** 記録に対する配置は、最初の編集の規則を記録から再現する。次の点は同じにならないことがある。
   - 1つのシーケンスの段落で、両側の変更より長い一致を含む1回の編集（「abc XXXXXXXX def」→「uvw XXXXXXXX xyz」）。最初の編集は全体を1つの変更とし、記録に対する配置は真ん中を元の文字として残す。
   - 新しい文字のグリフの選び方。最初の編集はページで最初に見つかった同じ文字の符号を使う。その文字がページから消えた後の編集では、別の手本になることがある。
   
   評価の37組では、どちらも差として現れなかった。
3. **記録の大きさ。** 記録に、文字ごとのサイズと、ページのフォントごとの値（トラッキング・詰め・句読点）が加わった。府政だより7ページの段落（C01、112文字）で、組版の記録は JSON で約 11.7 KB、条件の記録全体を Flate で圧縮して約 4.1 KB をページに加える。
4. **拒否は変わらない。** 長文化の拒否（後続段落の配置物、容量、保護された描画）と、C14 のサブセットのフォントの例外は、PR #92・#94 と同じ（4.1）。

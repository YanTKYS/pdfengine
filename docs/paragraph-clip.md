# 明示承認付きのレイアウト調整（第2段階）：Word のテキストボックスのクリップを縦に伸ばす

2026-11-02。Issue #118。PR #117 マージ後の main `f8158f5` を起点とする。評価条件は、実装前の `8bfe247` で [manifest](../evaluations/paragraph_clip/manifest.json) に固定した。結果は [results.json](../evaluations/paragraph_clip/results.json)。

## 結論

- **W1・W2（Word のテキストボックス）**：従来は本文のクリップで拒否していた長文化が、**クリップの延長とパネルの延長の両方を明示承認したときだけ**保存できるようになった。
  - 承認なし・クリップだけ・パネルだけの承認では拒否し、何も書かない。
  - 保存したPDFだけから、元に戻す編集もできる。クリップとパネルは、それぞれの承認で戻る。承認しなければそのまま。
- **実用成功**：
  - **W1：成功**（保存した手・戻す手の両方）。承認変更監査（承認・クリップ・パネル・本文・保護）、行ごとの検索・両抽出・コピー相当、自然な配置、意味構造・リンクがすべて合格。
  - **W2：不合格**（保存は成功）。元の文書が「FAX」を字間を空けて描いており、両方の抽出が「F A X」と読む。編集と関係のない、元の文書の隙間（`as_in_source` true）。Issue #116 の規則で、元由来でも合格にしない。
- 再編集はすべて成功（4手）。復元（戻す手で元の文書と比べる）は W1・W2 とも字形・画素・文字・リンクが一致。
- 既存の評価への影響：
  - `eval_hub` の通常の段階（スモーク・連鎖・装飾・忠実度・復元）：147記録で基準との違い 0。
  - パネルの評価：L2・L6・L8 は変わらない。W1・W2 はそこでは拒否のまま（パネルだけを承認するため）。拒否の理由が「容量」から「クリップの延長の承認も必要」に変わった。
- 承認したパネルの延長の書き換えを、上辺が数値として正確に元のまま残る形に直した（2.2）。L2・L6・L8 の結果は変わらない。

## 2. 方式（`prototypes/paragraph_frame/clip_extension.py`）

### 2.1 候補になる条件

段落の成長を止めているのが、段落の文字に設定された矩形のクリップのとき、そのクリップの延長を候補として示す。

- 段落の文字を描く、ページの内容ストリームにある（Form XObject は拒否）。
- クリップの各回の設定が、1つの `re` だけのパスで `W` または `W*` の後に `n`。軸に平行な CTM の下。同じ矩形の設定は、そのストリームのすべてを伸ばす。規則（`W`/`W*`）と順序は変えない。
- クリップが保持するのは文字だけ。どの回の下にも、塗り・線・画像・シェーディング・Form は描かれていない（あれば「伸ばすと見えるようになる」として拒否）。
- 段落以外の文字が、クリップの下端より下にない（隠れている文字が見えるようになるので拒否）。
- 段落の文字にかかる他のクリップは、すべて延長後のクリップを含む矩形（切られるなら拒否。矩形でないクリップも拒否）。
- 延長量は段落の増分（下の余白を保つ最小値）。上端・左右・規則は変えない。延長で加わる帯はページの中にあり、ボックスのパネル以外の何にも当たらない。
- 延長後のクリップがボックスのパネルの下端を越えるとき、パネルの延長（PR #113 の条件のすべて）を一緒に示す。パネルが伸ばせなければ、クリップも示さない（理由を示す）。

### 2.2 提案・承認・保存

- 提案の `evidence.clips.candidates` に示す内容：
  - 変更 ID（`clip-extension-…`）
  - 元の矩形と延長後の矩形、延長量、変える辺（下端だけ）、規則
  - 書き換える演算子（位置と元のバイト列。すべての回）
  - 保持するもの（文字の表示の数、段落の表示の数、図形 0）
  - 加わる帯、理由、承認しないときの振る舞い（拒否）
  - 一緒に必要なパネルの延長の ID（`requires`）。パネルの候補にも、クリップの ID が `requires` に入る。
- ID は、元PDFの digest、選択文字列・置換・出現番号、内容ストリームの digest、全演算子のバイト列、矩形と延長量から作る。別の PDF・別の編集・別の延長では ID が変わる。
- `propose(..., clips=[id], panels=[id])`（CLI は `--clip`・`--panel`）で両方を承認したときだけ伸ばす。
  - クリップだけ、パネルだけの承認は拒否する（理由に足りない ID を示す）。
  - `acknowledge_inference`、連鎖の承認、以前の編集の承認では伸びない。
- 保存では、各回の `re` の4つの数値を書き換える（下辺だけが動く）。
  - PDF の座標は y が上向きなので、下辺を動かすと `y` と `h` が変わる。上辺 `y + h` は、レンダラーの和（倍精度と単精度）が元と同じ値になる数値を選ぶ（`panel._keep_sum`）。そうしないと、輪郭の上辺のアンチエイリアスが変わる（W1 で見つけた）。パネルの延長にも同じ書き方を使う。
- 保存前の検査：挿入位置のクリップは、承認した延長後の矩形として読む。画素の比較の範囲は従来どおり（伸ばす場合、加わる帯は枠の中）。
- 保存記録 `clips_extended`。段落の記録（PieceInfo）に、元の矩形・延長後の矩形・承認と、**すべてのインスタンス（ストリームの順に、書き換えた演算子と規則）とその数**を残す（PR #119 のレビュー）。

### 2.3 保存したPDFだけからの再編集

- 再open すると、記録したクリップの延長が「承認どおり設定されている」かを照合して、`evidence.conditions.clips` に示す。照合する内容：
  - 段落の文字が記録した矩形のクリップの下にある。
  - 延長後の矩形のクリップの設定が、記録した数だけある。ストリームの順に、各インスタンスの演算子の文字列と規則が記録と同じ（欠け・追加・大きさの変更・規則の変更・別のクリップへの置き換えは、すべて stale。PR #119 のレビュー）。
  - 元の矩形のクリップが残っていない。
  - 図形・画像を保持していない。
- 1つでも違えば、段落の記録を適用しない（stale。理由を示す）。
- さらに長くする編集では、新しい延長を新しい ID で示し、改めて承認を求める。
- 短くする編集では、クリップとパネルを戻す候補（延長前の位置より上には戻さない）を ID で示す。承認しなければそのまま。

### 2.4 監査（`approved_audit`）

- 変更の種類 `clip` を加えた。
  - 保存後のクリップ（MuPDF の拡張描画）を描画の順に並べたものが、元のクリップの並びで承認した矩形の各インスタンスだけを延長したものと、1つずつ一致する（数・規則・順の位置。ほかのクリップも同じ。PR #119 のレビュー）。元の矩形は残らない。
  - 加わる帯に、編集した段落の新しい文字と承認したパネル自身の描画のほかは、文字・図形・画像がない。
- 承認の照合に `clips` を加えた（承認した ID がこの提案の候補であること、承認なしの延長がないこと）。
- 既存の監査（`indesign_evaluate.audit`）は変えず、並べて記録する。

## 3. 実PDFの評価（`clip_evaluate`）

## 6. 判断事項

設計者の方向（PR #119 のレビュー）。どれもこのPRでは現状のまま。

- 1：操作ごとに推定を明示承認した範囲に限り、既定値 15.84 pt を保つ。他の行の 18 pt を根拠に変えるかは別の Issue で比べる。
- 2：文字が見切れず、それぞれが独立に承認され、保護の監査も通るなら、片方だけ戻すことを許す。対称性だけを理由に両方を必須にしない。
- 3：字形・画素が同じなら、主な目的の妨げにしない。元の演算子への完全な復元は、独立した改善の候補。
- 4：元由来の隙間は不合格のまま。
- 5・6：組み合わせて示す仕様は Issue #118 の範囲として妥当。同じ矩形のクリップを一括で扱うには、個数と各インスタンスの検証が必要（7章で対応）。

1. **追加の行の行送り**
   - W1・W2 の段落は1行で、行送りを観測できない。既定値（1.5 em = 15.84 pt）で追加の行を置き、保存時に推定として承認している。ボックスの他の行の間隔は 18 pt。
   - 自然な配置の確認は「提案の位置どおり」で合格（Issue #116 の方針）。見た目の自然さを利用者が画面で確かめた証拠ではない。
   - 代替案：同じボックスの他の段落の間隔（18 pt）を行送りの根拠にする（推定の規則の変更）。
2. **クリップとパネルを別々に戻せること**
   - 元に戻す編集では、クリップとパネルの候補をそれぞれ示し、どちらか一方だけの承認でも保存する（文字は短くなるので見切れない）。伸ばすときは両方を求める。
   - 代替案：戻すときも両方をそろえて求める。
3. **復元の厳密さ**
   - 元に戻すと画素・字形は元と同じ。演算子の数値は 0.000003 pt 以内で元と違う（上辺を正確に保つため）。
   - 代替案：元の演算子の文字列を記録しておき、元の位置に戻すときはそれを書く。
4. **W2 の実用成功**
   - 元の文書の字間（「F A X」）で段落の抽出が一致しない。Issue #116 の判断事項 1 と同じ。元由来の救済はしていない。
5. **製品契約の変更**（Issue #118 で承認された範囲）
   - クリップされたパネル（`test_paragraph_panel` の期待）：Issue #112 では「クリップは延長しない」として候補を出さなかった。今回は、パネルの候補を、クリップの延長と一緒に必要なものとして示す。パネルだけの承認では拒否のまま。
   - パネルの評価の W1・W2：結果は拒否のまま。理由が変わった（固定評価の結果ファイルを更新した。期待は「拒否」で同じ）。
6. **同じ矩形のクリップ**
   - 同じストリームで同じ矩形を設定しているクリップは、すべて同じボックスのものとして伸ばす。そのすべてが文字だけを保持し、隠れた内容がないことを確かめている。
   - 実PDFは Word の2件だけ。他の生成器のテキストボックスは確かめていない。

## 7. レビュー対応（PR #119）：クリップのすべてのインスタンスを照合する

- 問題：W1 は同じクリップを15回、W2 は28回設定している。修正前の監査は、元の矩形が残っていないこと・新しい矩形が1つ以上あること・規則の種類の集合だけを見ていた。再open の照合も、演算子の文字列の集合と規則の集合だけを見ていた。そのため、インスタンスが1つ消えても「承認どおり」になりえた。
- 修正：
  - 監査：元のクリップを描画の順に並べ、承認した矩形の各インスタンスを延長後の矩形に置き換えたものが、保存後の並びと1つずつ一致することを求める（数・規則・順の位置。ほかのクリップも含む）。
  - 記録：すべてのインスタンス（ストリームの順に、書き換えた演算子と規則）とその数を残す。

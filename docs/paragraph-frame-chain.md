# 長文化で衝突する後続の行・装飾を、明示承認で連鎖移動する

2026-10-28。Issue #103。PR #102 マージ後の main `a7bb571` を起点とする。評価条件は、実装前の commit `e7ce0ce` で [manifest](../evaluations/paragraph_frame_chain/manifest.json) に固定した。結果は [results.json](../evaluations/paragraph_frame_chain/results.json)。

## 結論

- 長文化で段落が下の行に当たるとき、**当たる行（とその行の装飾・配置物・リンク）を「連鎖の要素」として根拠とともに提案に示し、すべての要素の id を明示的に承認したときだけ**、後続段落と同じ移動量で動かすようにした（2章）。
  - `acknowledge_inference` や行の装飾（PR #100）の承認では、連鎖の要素は動かない。
  - 連鎖は全要素を一緒に承認したときだけ動く。一部だけの承認は拒否する。
- **固定した実PDFの9件（PR #100 で拒否された長文化7件と、調査で見つけた p2 の2件）は、すべて拒否のまま**（目標未達）。
  - 9件とも、描画の証明を外して幾何だけで判定しても、1行分が収まらない。下の行を動かすと、次の記事の見出し枠、広告枠の上の全幅の罫線、または横に並ぶ段の共通の下端に当たる（1章）。
  - 枠を広げたり、衝突の判定を外したりしても安全な編集にはならないので、容量の拒否を維持した。
  - 9件とも、拒否の理由（どの行が、何に当たるか、または何と一緒に描かれているか）を提案の証拠 `evidence.chain` に示す。
- **固定の後**、実装した判定で実PDF 25文書・35ページの全段落（1,250）を調べ、連鎖が成り立つ場所を探した（4章）。
  - 見つかった実PDFの2件を、固定とは別の「追加ケース」として評価した。
  - **2件とも、従来は拒否（容量）、今回は連鎖を承認して保存できた。**
    - S1：pdf.js コーパスの issue17730（Antenna House の文書）。見出しを1行増やし、下のリンク付きの5行を動かす。
    - S2：LibreOffice の文書 lo_migration_ja。脚注を1行増やし、その下の行を動かす。
  - 2件とも、次の監査に合格した。
    - 移動の監査：移動した要素の字形・描画・リンクが正確に平行移動し、元の位置に何も残らない。ほかの描画は不変。
    - リンクの監査、配置（ページの中、動かない描画の上に出ない）、移動した範囲の画素。
    - 品質（MuPDF・Poppler の抽出と検索）、構造、保存したPDFだけからの再編集。
  - 保存したPDFだけから元に戻す編集も 2/2 で保存した。元のPDFと比べて、字形の原点（0.001 pt）・描画・リンク（`/Rect`・`/QuadPoints`、0.001 pt）・抽出・画素（72・150 dpi）が同一。
  - S2 は、増えた行が脚注番号の位置から始まり、ぶら下げ字下げにそろわない。既存の段落推定が脚注の2行目を別の行と判定するためで、連鎖とは別の課題として残す（5.2）。
- **既存の安全性監査（`indesign_evaluate.audit`）は緩めていない。** 連鎖を承認した手では、評価器の領域の外で要素が動くので、領域外の画素・字形の不変と `non_text_paint_identical` が不合格になる。そのまま不合格として記録し、移動専用の監査を別に示す。
- 既存機能：PR #87〜#102 の回帰は 6章。

## 2. 方式

`prototypes/paragraph_frame/chain.py`。

### 2.1 連鎖の要素

- **行**：段落（編集する段落と後続段落）より下で、その段にかかる段落群（`auto_detect` の `chain_rows`、近い順に12まで）。
  - 縦に重なる段落群は1本の行とする。たとえば HP 行は、アイコンと検索欄の文字が溝で別の段落群に分かれる。
  - 段落の行に重なる段落群（後続段落の検索欄の文字）は、その行のものとして除く。
- **連鎖**：移動量 Δ（後続段落と同じ）に対し、動くものの下端から Δ 以内に上端がある行を、近い順に加える。加えた行の分だけ範囲が下に延びる。
- **要素**：行の描画（`decoration.group` で証明する。PR #100 と同じ条件）。
  - 行の字形をすべて含み、ほかの段落・ほかの行の字形を含まない、連続した項目。
  - 行の範囲（slot）：上下の隣の行の文字まで。横は、行の文字または枠の端から 1 em 外まで（検索ボタンのポインタが段から出る）。
  - 行の直前に、その行の範囲で続けて描かれた項目も含める（自分のクリップの下の下線）。
  - 行の描画が下の行も一緒に描く場合（複数行のテキストオブジェクト）は、下の行と合わせて1つの要素にする（8行まで）。
  - 描き直さないので、字形の判定は描画の判定だけ（`movable_line`）。符号と結びつかない字形（タブ）は、その描画が運ぶ。
- **拒否**：次のどれかで、連鎖は成り立たず、成長は容量で拒否のまま。理由を証拠に示す。
  - 行が1つの描画として動かせない：行の外の内容と一緒に描かれる、釣り合わない、構造の印、Form XObject の中、クリップが移動先を含まない、背景から出入りする、行の外に届くリンク、行の上の別の描画・注釈。
  - 移動先で、動かない描画・文字・画像に当たる。
  - ページの外に出る。横に並ぶ段の共通の下端を越える。
  - 当たるのが行ではない（罫線・パネルの端・見出し枠）、または要素を動かしても段落がまだ何かに当たる。
- 高さや幅のない線（罫線のストローク）も、細い帯として判定する。行の描画に重なる別の描画を行のものとみなすのは、画像（XObject の中）だけにした。

### 2.2 提案と承認

- 提案の `evidence.chain` に、次を示す。
  - 移動量、連鎖が必要か、承認したときの枠の下端。
  - 要素ごと：順、行の文字、演算子の範囲と数、バイト列の sha256、範囲と移動先、描画数・シェーディング数・XObject、運ぶ文字、配置物の数、再設定する状態、リンク（xref・矩形・URI）、近くの内容、枠の下端の前後。
  - 成り立たないとき：その理由（`unavailable`）。
- id は上の証拠の digest（`following-element-…`）。`propose(..., chain=[ids])`、CLI は `--chain <id>`（繰り返し）。
  - 一覧にない id、一部だけの承認、成り立たない連鎖の承認は拒否する。
- 承認がないとき、連鎖が必要な成長は「下の行に入り込む。要素 … は明示的に承認したときだけ動く」で拒否する。
- 後続段落の行の装飾（PR #100）の候補は、連鎖を承認した提案では、連鎖の要素も一緒に動くものとして判定する。

### 2.3 容量

- 承認した連鎖では、枠の下端を次のどちらか近いほうまで下げる。
  - 段落より下で、動かない保護された描画のうち最初のもの。
  - 最初の要素の移動先。
- 枠の container（背景）とテキストのクリップの下端は越えない。枠の幅は変えない。
- ページの外への押し出し、縮小、白塗り、重なりによる見かけ上の成功はしない。保存前の検査（新しい字形は枠の中、保護された描画と重ならない）は従来どおり。

### 2.4 書き込みと保存前の検査

- 要素を `q 1 0 0 1 tx ty cm <要素> Q <状態の再設定>` と書く（PR #100 と同じ）。元の演算子は変えない。
- リンクの `/Rect`・`/QuadPoints` を同じ量だけ動かす。リンク先・フラグ・外観は変えない。
- 保存前の検査は、要素を承認した移動として、PR #100 と同じ方法で確かめる。
  - 字形は正確に平行移動（0.001 pt）。要素の中の描画・画像は移動量だけずれる。それ以外は完全に不変。
  - **注釈を PDF の辞書のまま比べる検査を加えた。** 移動した注釈は `/Rect`・`/QuadPoints` が移動量だけずれ（0.02 pt）、それ以外の内容（リンク先のページ・アクション・外観）は同一。ほかの注釈は完全に同一。
    - PyMuPDF の一覧に出ないリンク（S1 の ID へのリンク、外部ファイルへのリンク）も確かめる。
- 保存記録に `chain_moved`（id・範囲・移動量・字形数・リンクの元と移動先・行）を加えた。
- 要素の行は、PR #102 の `/PieceInfo` の `moved` に記録する。保存したPDFを開き直したとき、行の観察を元の PDF と同じにする。

### 2.5 元に戻す

- 段落が短くなるとき、下に続く行（同じ規則で、動くものの下端から |Δ| 以内）を、任意の候補として示す。
- 承認すると一緒に上へ動く。承認しなければ、従来どおり行はその場に残る。
- 長文化で承認した id は使い回せない。元に戻す編集の候補は、その編集のもの（id が違う）。

## 3. 固定した評価

実装前（`e7ce0ce`）に固定した。

- **対象**：
  - PR #100 で拒否された長文化7件（P7-03・P7-05・P7-06・P8-08・P8-09・P8-11、C02 の PR #92 の長文化）。
  - 調査で見つけた府政だより477 p2 の2件（P2-R・P2-L）。段落の字形で1行分を足す。
  - 生成した fixture：
    - F1：下に空きがある。
    - F2：下の行のすぐ下に罫線がある。
    - F3：パネルが行のすぐ下で終わる。
- **手順**：各手で次を行う。
  1. 提案し、連鎖と行の装飾の候補を記録する。
  2. 承認せずに保存する（候補が必要な手は拒否されること）。
  3. 示された候補だけを承認して提案し直し、新しい候補が出なくなるまで繰り返す（3回まで）。そのうえで保存する。評価器が、候補を読んだ利用者の代わりに承認する。従来B2 には連鎖の手段がない。
  4. 保存したPDFだけから元に戻す。同じ手順で承認する。
- **測るもの**：
  - 保存・拒否、既存の監査（安全性と品質を分ける）、構造、再編集。
  - 移動の監査、リンクの監査、配置（ページの中、動かない描画の上に出ない）、移動した範囲の画素。
  - 元に戻した結果と元のPDF：字形の原点（0.01 pt、0.001 pt）、改行、MuPDF・Poppler の抽出、検索、描画、画像、リンク（0.001 pt）、構造。画素（72・150 dpi）は別項目。

固定の後に変えたこと（固定したケース・編集・基準は変えていない）：

- 評価器の進行表示で、元に戻した結果の項目名（`links`）が移動の監査と重なり、例外で止まった。表示の項目名を変えた（`8e33529`）。結果の記録は変わらない。
- 追加ケース（`supplement`）を manifest に加えた（4章）。固定したケースとは別に集計する。

## 4. 固定の後の調査と追加ケース

固定した9件がすべて拒否のままだったので、実装した判定で、ほかの実PDFを調べた。

- **対象**：これまでの評価で使った実PDF 25文書・35ページ。府政だより477、LibreOffice・Word の文書、pdf.js のコーパス。issue8702 の1ページはエラーで終わった。
- **方法**（`chain_survey.py`）：全段落（1,250）を編集の対象として検出し、1行（推定した行送り）の成長で連鎖が成り立つかを調べた。調べたコードは、`47e47f2` と `e4487b6` の間の作業中の版。
- **結果**：

| 結果 | 段落 |
|---|---|

- 成り立たない主な理由：

  - タグ付きの文書で、行が複数の構造要素にまたがる：108。
  - 行の上に、行の描画の外の塗り：34。
  - 背景から出入りする：29。
  - そのほか（[results.json](../evaluations/paragraph_frame_chain/results.json) の `survey`）。
- 成り立つ16か所で、段落の先頭の文字列を足して1行分の成長を作り、保存を試した。
  - 12か所は編集が作れなかった：足した文字列に段落のフォントにない字形がある（6）、改行できる位置がない（5）、フォントを読めない（1）。
  - issue14117 の2か所：成長の量では、行の上に描画の外の塗りがあり、連鎖が成り立たない。
  - issue17730 の2か所：保存前の検査で拒否された。調べると、各行のリンクの下線が行の直前に描かれ、要素から漏れていた。高さのない線のため、行の上の内容の判定もすり抜けていた。PyMuPDF の一覧に出ないリンクもあった。2.1・2.4 のとおり直した（`e4487b6`）。
- 直したあと、issue17730 の見出しと、字形のある編集に変えた lo_migration_ja の脚注（調査で成り立った1か所）が保存できた。この2件を、固定の手順で評価した（`chain_evaluate.py --phase supplement`）。

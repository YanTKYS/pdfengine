# 後続段落の行の装飾（検索欄・リンク注釈）：明示の承認で一体に移動する

2026-10-27。Issue #99。PR #98 マージ後の main `3c81178` を起点とする。評価条件は、実装前の commit `ccbfc74` で [manifest](../evaluations/paragraph_frame_decoration/manifest.json) に固定した。結果は [results.json](../evaluations/paragraph_frame_decoration/results.json)。

## 結論

- 後続段落の行にある装飾（府政だよりの「HP」行の検索欄・ボタン・ポインタ・検索文字・リンク注釈）を、**候補として根拠とともに提案に示し、その候補の id を明示的に承認したときだけ**、段落と同じ移動量で一体に動かすようにした（2章）。
  - `acknowledge_inference` だけでは承認にならない。
  - この編集の候補でない id（別の編集、承認後に変わったPDF）は拒否する。
- **実PDFで、新たに4手を保存できた**（府政だより477 p7 の短文化：P7-03・P7-05・P7-06・P7-07＝C02）。従来B2（`3c81178`）はこの14手をすべて拒否していた。
  - 4手とも、次の監査に合格した。
    - 移動の監査：移動した描画13・文字・画像が移動先に正確にあり、元の位置に残らない。
    - 保護の監査：それ以外の描画・画像は不変。
    - リンクの監査：リンク先は不変、移動したリンクの矩形は正確に平行移動、ほかのリンクは不変。
    - 構造・検索とコピー（品質）・保存したPDFだけからの再提案。
  - 承認しないと、4手を含む候補のある6手すべてを拒否した。
- **既存の厳格な監査（`indesign_evaluate.audit`）は緩めていない。** 承認した移動がある手は、その `non_text_paint_identical`（非文字の描画がすべて不変）が不合格になる。そのまま不合格として記録し、移動の監査・保護の監査・リンクの監査を別に示す（4章）。
- 残るもの：
  - **長文化はすべて拒否のまま**（9手）。HP 行が下の「問」の行のアイコンなどに重なる（衝突）。Issue のとおり、容量・衝突の拒否は維持した。
  - **画素の完全一致**：移動した行の描画を、移動量が整数画素になる倍率で比べた結果は、P7-07 が完全一致。P7-03・P7-05 は 9 サンプル（最大 3/255）、P7-06 は 2 サンプル（1/255）の差で、不合格として記録した。差は検索ボタンのシェーディングの位置にあり、MuPDF がシェーディングを装置の格子に合わせてラスター化するため。
  - **保存したPDFだけからの元に戻す編集**は、C02（P7-07）だけが保存できた。P7-03・P7-05・P7-06 は拒否（4.3）。
- 既存機能：PR #87〜#98 の回帰は 5章。

## 1. 対象の分類（実装前）

PR #98 で、後続段落の行に動かない内容があるとして拒否した13手と、移動先の衝突で拒否した1手、PR #92 の C02 の長文化を対象にした。容量とグリフ不足の拒否は対象外。

府政だより477 p7 の C02 の HP 行（ページの内容ストリーム、524演算子）は次のとおり。

| 部分 | 演算子 | 備考 |
|---|---|---|
| アイコン | 背景の `re f`、`/PlacedPDF BDC q … EMC Q` | PR #98 の単位 |
| HP 段落の空白 | `BT … Tj ET` | HP 段落の字形 |
| 検索欄 | 白の `re f`、灰色の罫線2本（`q cm m l S Q`） | 印なし |
| 検索文字 | `BT … TJ ET`「■大阪府　原状回復」 | **どの段落群にも属さない字形**（HP 段落とは別） |
| ボタン | 角丸のクリップ＋シェーディング `sh`、全ページのクリップ下の枠線、「検索」の字形のパス | 印なし |
| ポインタ | パス＋ `Do /Fm4`（GS6） | Form XObject |
| 状態の設定 | `k`・`gs`・`K`・`w`・`M`・`j`・`J`、BT 内の `Tc`・`Tw`・`Tf` | 後の内容が読む |
| リンク注釈 | xref 1911、`/Rect` が検索欄とボタンの上 | URI |

- 段落との関係を示すのは、位置と、アイコンから続く描画の連続だけ。
- 状態の設定がグループの深さにあるため、`q … Q` で囲むだけでは後の内容の状態が変わる。
- p8 の検索ボタンは推定した本文の枠より右に出る。

## 2. 方式

`prototypes/paragraph_frame/decoration.py`。後続段落の配置物が、行の上の別の内容のために動かせないとき（PR #98 の拒否）に、**候補のグループ**を作る。

### 2.1 候補

- **始まり**：段落の配置物（PR #98 の単位）または段落の文字のテキストオブジェクト。
- **続き**：まとまった項目（パスと塗り、`q … Q`、テキストオブジェクト、印の範囲、XObject）を、行の範囲に描かれる限り続ける。
  - 行の範囲は、段落とその配置物・運ぶ文字の帯の上下 2 pt。
  - 横幅は、その列の枠か、列の幅の2倍未満であれば列を囲む背景の枠。
- **文字**：段落の字形をすべて含み、編集する段落・ほかの後続段落の字形を含まない。
  - どの段落群にも属さない行の上の字形（検索文字）は「運ぶ文字」として含め、証拠に列挙する。
  - 符号と字形の対応が取れない字形は、同じ演算子の文字と原点が 0.01 pt で一致し、ほかに対応する文字がないときだけ含める。
- **場所**：ページ自身の内容にある（Form XObject の中は拒否）。両端はテキストオブジェクト・パス・クリップの外。`q`/`Q` と印の範囲は対応している。
- **グループの深さで許すもの**：項目を描くこと、状態を設定すること（色・ExtGState・線・文字状態）。CTM・クリップ・シェーディングをこの深さで設定するものは拒否。
- **状態の再設定**：グループの後に、この深さで使った状態の設定を同じ順に再び書く。後の内容が読む状態は元と同じになる。
- **行に残るもの**：段落の行（その列）に、グループと段落の文字以外の描画・文字・画像・注釈があれば拒否。
- **移動の前後**：
  - 受け継ぐクリップは矩形で、移動の前後のグループを含む。
  - 移動先に保護された描画・文字があれば拒否。
  - 背景は移動の前後を両方含む。
  - ほかの後続段落の配置物（同じ量だけ動く）は障害物にしない。
- **注釈**：行の上の注釈は Link だけ。グループの範囲の中にあり、このページだけが参照する。同じ移動量で `/Rect` と `/QuadPoints` を動かし、リンク先・アクション・フラグ・外観は変えない。ほかの注釈は拒否。
- **自分の描画**：項目ごとの描画範囲で判定する（外接矩形全体では判定しない）。項目に重なる行の上の描画（XObject の中の画像など）もグループのものとし、保存前の検査で、正確に移動したことを確かめる。

### 2.2 提案と承認

- 提案の `evidence.decorations.candidates` に、候補ごとに次を示す。
  - 対象ページ・段落
  - 演算子の範囲と数、バイト列の sha256
  - 範囲と移動先、移動量
  - 描画数・シェーディング数・XObject
  - 段落の字形数・運ぶ文字・配置物の数
  - 再設定する状態
  - 注釈（xref・矩形・URI）
  - 移動先の近くの内容の種類
- 候補にならなかった後続段落は、`unavailable` に理由とともに示す。
- id は上の証拠の digest。`propose(..., decorations=[id])`、CLI は `--decoration <id>` で承認する。
- 承認した id は提案に入り、承認の確認（`approve`）と保存（`save`）でも、同じ候補が再び得られることを確かめる。
- 承認がないとき：PR #98 と同じ理由で拒否し、承認が必要な候補の id を理由に添える。

### 2.3 書き込み

- グループを `q 1 0 0 1 tx ty cm <グループ> Q <状態の再設定>` と書く。元の演算子は変えない。
- 移動量は、グループの前の CTM とページの変換から、倍精度で求める。PyMuPDF の行列は単精度で、ページ下端では 6e-5 pt ずれ、描画の比較に現れた。PR #98 の単位にも同じ計算を使う。
- 段落の字形と運ぶ文字は書き直さない。
- リンクの `/Rect`・`/QuadPoints` を同じ移動量だけ動かす。
- 新しい文字を、移動する単位・グループの内側には書き込まない。

### 2.4 保存前の検査

従来の検査は緩めていない。承認した移動と、それ以外を分けて確かめる。

- **文字**：移動した単位の字形（運ぶ文字を含む）は、移動量だけ正確にずれている（0.001 pt）。コード・フォント・大きさ・色・描画モードも同じ。
- **描画**：単位の内側は移動量だけずれている（0.02 pt。移動量の丸めが 0.01 pt のどちらにも転ぶ）。それ以外は完全に不変。
- **画像**：
  - 単位の内側で画素データが同じ画像は、移動量だけずれている（0.02 pt）。
  - シェーディングのラスターは、装置の格子に合わせて画素数と位置が変わる。グループのシェーディング数以下で、移動先の範囲の中にあり、色空間が同じであることを確かめる。
  - それ以外は完全に不変。
- **リンク**：承認したリンクは同じリンク先で移動先にあり、ほかのリンク・注釈は不変。
- **枠の外のラスター**（MuPDF・Poppler）：マスクに加えるのは、単位の元の位置と移動先だけ。

保存記録に `decorations_moved`（id・範囲・移動量・字形数・リンクの元と移動先）を加えた。

## 3. 固定した評価

実装前（`ccbfc74`）に固定した。

- **実PDF**：10ケース・14手（1章）。
- **生成した fixture**：`tests/test_paragraph_frame_decoration.py` の作り方。
  - D1：アイコン・文字・検索欄とリンク。長文化と短文化。
  - D2：検索欄の色をグループの深さで設定する。
  - D3：グループの外まで届くリンク。
  - D4：グループの深さのクリップ。
  - D5：行の上の別の塗り。
- **手順**：各手で次を行う。
  1. 提案して候補を記録する。
  2. 承認せずに保存する（候補が必要な手は拒否されること）。
  3. 示された候補だけを承認して保存する。評価器が、候補を読んだ利用者の代わりに承認する。従来B2には承認の手段がない。
  4. 保存したPDFだけから元に戻す。その提案が示す候補を承認する。
- **測るもの**：
  - 保存・拒否、既存の監査（安全性・品質、編集した段落と後続段落の領域）、構造、再提案。
  - 移動と保護の監査（評価器の独立の実装）、リンクの監査。
  - 移動した行の画素（移動量が整数画素になる倍率、MuPDF、完全一致）。
  - 元に戻した結果と元のPDF。

固定後に見つけて直した評価器の問題（ケース・編集・基準は変えていない）：

- PR #98 の配置物の監査は、承認したグループの移動を知らなかった。グループも含めて、移動と保護を分けて確かめる監査に置き換えた。
- 移動したリンクを、x0 を小数2桁に丸めて特定していた。全座標を 0.01 pt で照合するようにした。
- シェーディングのラスターを画素数込みで照合していた。2.4 と同じく、数と色空間で照合するようにした。見た目は画素比較で確かめる。

## 5. 既存機能への影響

評価したコード（`6b68494`）で、PR #87〜#98 の評価を各PRと同じスクリプト・入力で実行し直し、PR #98 が記録した状態（main `d1207db`）と比べた。結果は results.json の `regression`。

| 評価 | PR #98 が記録した状態との違い |
|---|---|
| PR #87〜#91（`tagged_regression.py`：一般化・連続性・段組・InDesign・タグ付き） | **0**（PR #96 の記録とも 0） |
| PR #92 の固定評価 | 0（C02 の長文化は PR #98 と同じ理由で拒否） |

| PR #96 の複数の編集 | 0（集計・各手とも同じ） |
| PR #98 の後続段落の配置物 | 集計は同じ。拒否理由の文言が1手だけ変わった（下記） |

PR #98 の P8-09 の長文化：

- 従来：`… would collide with protected filled-vector`
- 今回：`… would collide with protected vector`

同じ段落の配置物（「日」「定」「申」のアイコン）は一緒に動くので、互いを障害物にしないようにした（2.1）。そのため、衝突の相手が別の描画（罫線）になった。拒否のまま。

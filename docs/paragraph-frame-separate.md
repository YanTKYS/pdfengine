# 複数の行を描くテキストオブジェクトから、後続の行を分離して動かす

2026-10-28。Issue #105。PR #104 マージ後の main `11a9aa7` を起点とする。評価条件は、実装前の commit `ec19c50` で [manifest](../evaluations/paragraph_frame_separate/manifest.json) に固定した。結果は [results.json](../evaluations/paragraph_frame_separate/results.json)。

## 結論

- 後続の行がほかの文字と同じテキストオブジェクト（BT…ET）で描かれるとき、**行を描く演算子だけを取り出し、内容の中の同じ位置で別のテキストオブジェクトとして平行移動して描き直す**ようにした（2章）。
  - 演算子は切らない。文字行列・字間・カーニング・フォント・色・ExtGState・クリップ・描画順・抽出順を保つ。
  - 証明できないとき（1つの演算子が行とほかの文字を描く、ソフトマスク、MCID、文字のクリップなど）は理由とともに拒否する。
  - 分離は連鎖の要素（PR #104）の証拠 `evidence.chain` に `separated` として示し、要素の id を明示的に承認したときだけ動く。
- **実PDFで、従来は拒否された長文化が新たに3件保存できた（目標達成）。** 固定した 25件のうち R02・R13・R18（従来B2 は 25件すべて拒否）。
  - R02：pdf.js コーパス issue17730 p2。「See also …」の行（リンク付き）を、見出しと同じテキストオブジェクトから取り出した。
  - R18：府政だより477 p5。3行を取り出した。うち2行は、ほかの文字の間（テキストオブジェクトを終えて再開する）から取り出した。
  - R13：府政だより477 p4。1行を2つの演算子として取り出した。
  - 3件とも、動かさない内容（字形・MuPDF と Poppler の単語と順序・描画・72/150 dpi の画素）が不変、動かした行の単語の順序も同じ。品質（抽出・検索）、構造、保存したPDFだけからの再編集に合格した。
  - **保存したPDFだけから元に戻す編集**：R02・R18 は保存し、元のPDFと字形の原点（0.001 pt）・抽出・検索・描画・画素（72・150 dpi）が同一。R13 は元に戻せない（5.2）。
- 残る 22件は拒否のまま。理由は描画の単位ではなく、ほとんどが幾何・容量（5.1）。
  - 行の帯に動かない内容（画像・図形・別の文字）がある 10件、背景から出入りする 9件、容量 2件。
  - 描画の単位の制約が残るのは R10 の1件（1つの `TJ` が行とほかの文字を描く。演算子は切らない）。
- PR #104 の固定した9件は、すべて拒否のまま（容量・保護された内容）。分離で解決したとは数えない。4件は、拒否の理由が「一緒に描かれる」から幾何の理由に変わった。
- 生成した fixture は G1・G2・G4 を保存し元に戻した（画素まで同一）。G3・G5・G6 は理由とともに拒否した。G4 は固定時の期待（拒否）と違い保存した（6.1）。
- 既存の安全性監査（`indesign_evaluate.audit`）は緩めていない。行を動かした手では、評価器の領域の外で要素が動くので、領域外の画素・字形の不変が不合格になる（PR #104 と同じ）。分離専用の監査 `kept` を別に示す。
- 既存機能：PR #87〜#104 の回帰は 7章。PR #104 の連鎖の評価で、元に戻す編集が後退していたのを直した（`dd3ea7e`、6.2）。

## 1. 対象の分類

PR #104 の調査（実PDF 25文書・35ページの全段落）で、連鎖が「後続の行が行の外の内容と一緒に描かれる」で拒否された場所は 340 ある。描画の単位の制約を外し、各要素を独立に動かせると仮定した幾何だけの判定（`chain_geometry.py`）で、次のように分かれる。

| 分類 | 件数 | 意味 |
|---|---:|---|
| 収まる | 43 | 要素を動かせば、1行分が収まる |
| 保護された内容 | 202 | 動かした要素が、動かない描画・画像・文字に当たる |
| 段の下端 | 71 | 横に並ぶ段の共通の下端を越える |
| 容量 | 24 | 要素を動かしても、段落がまだ何かに当たる（C02 と同じ型） |

分離で助けられるのは「収まる」43件だけである。ほかの 297件は幾何・容量の制約であり、分離では解決しない（分離で解決したとは数えない）。

43件のうち、従来B2（main `11a9aa7`）で段落自身の文字で約1行長くする編集が作れ、連鎖が描画の共有で拒否された 25件を、実PDFのケース R01〜R25 とした。残る 18件は編集が作れない（改行位置なし 6、字形の欠落 10、行が増えない 2）。manifest の `no_edit` に理由とともに記録し、実行しない。

PR #104 の固定した9件（C02 と装飾の7件、p2 の2件）も再評価する。この9件の制約は容量と保護された内容で、描画の単位ではない。

生成した fixture G1〜G6（`tests/test_paragraph_frame_separate.py`）は、実PDFとは分けて数える。

## 2. 方式

`prototypes/paragraph_frame/decoration.py` の `separate`。連鎖の要素（PR #104）を作るとき、行の字形を描くテキストオブジェクトがほかの文字も描くなら、行を描く演算子だけを取り出して、別のテキストオブジェクトとして描き直す。

### 2.1 取り出す単位と、残る文字が変わらない条件

- **演算子を切らない。** 文字表示の演算子（`Tj`・`TJ`・`'`）は、行の字形だけを描くか、行の字形を1つも描かないかのどちらか。両方を描く演算子（1つの `TJ` が行とほかの文字を描く）は拒否する。
- 取り出した演算子は、元のバイト列（符号・カーニング）のまま描き直す。`'` は取り出した後に `T*` を残し、行列の移動を保つ。`"` は拒否する。
- 取り出した演算子の後で残る最初の文字表示は、`Td`・`TD`・`T*`・`Tm`（または `'`・`"`）で位置を決める。これらは行列（line matrix）を読み、文字表示は行列を変えないので、残る文字の位置は変わらない。行の終わりから続けて描く文字（位置決めなし）は拒否する。
- テキストオブジェクトの中に `q`・`Q`・`cm`・インライン画像・`Do`・`sh`・`BX` がある場合、文字がクリップする場合（描画モード 4〜7）は拒否する。
- 取り出す行は塗り（モード 0）か不可視（モード 3）で、色はデバイス色空間か名前付きの色空間に限る（パターンは拒否）。

### 2.2 描き直す場所と状態

- 描き直しは `q 1 0 0 1 tx ty cm BT <状態> <元の Tm> <元の演算子> … ET Q`。
- **内容の順序を保つ。** 行がテキストオブジェクトの最初の文字なら直前に、最後の文字なら直後に置く。ほかの文字の間にあるなら、行の位置で `ET` してから描き、`BT <その位置の行列> Tm` で再開する（文字の状態は `ET` を越えて残る）。抽出の順序（MuPDF・Poppler）は変わらない。
- 状態は、描き直す位置の状態と違うものだけを設定する：フォントとサイズ、`Tc`・`Tw`・`Tz`・`Ts`・`Tr`、塗りの色。
- **ExtGState（InDesign の透明・オーバープリント）**：テキストオブジェクトの中の `gs` は、行が読んだ値と描き直す位置の値が違うとき、同じ名前で設定し直す（最後の1つで足りればそれだけ）。ソフトマスク（設定した時点の CTM に固定される）やフォントを持つ ExtGState は拒否する。行の後に設定された値を戻せないとき（行が読んでいない値が残る）も拒否する。
- **marked content**：MCID を持つものは拒否する（構造は保守的に扱う）。MCID のない span（InDesign のタブを空白で描く ActualText）は、行の演算子だけを含むなら行と一緒に移す（span の `Tm` などはその場に残す）。行とほかの文字の両方を含む span、入れ子の span は拒否する。
- **抽出で照合できない字形**（InDesign のタブを描く CID 1 など、MuPDF の抽出に現れない字形）：行の字形のベースラインにあり、段の中にあれば行のもの、そうでなければほかの文字として扱う。1つの演算子で両方なら拒否する。
- クリップは、行の元の位置と移動先の両方を含むこと。
- Form XObject の中の行は扱わない（PR #104 と同じく、ページの内容だけ）。

### 2.3 行の他の部分

- 行のアイコン・検索欄など、テキストオブジェクトの外の描画は、PR #104 と同じく `q cm … Q` で包んで動かす。
- 行の描画の間に、行から完全に外れた描画があるとき（その場に残る）、それを飛ばして行の描画を複数の範囲として動かす。行に一部だけ重なる描画があれば、そこで止める（拒否の理由は「行の外の内容を持つ」）。
- InDesign の配置物 `BDC q … EMC Q` を、後ろから辿るときも1つの項目とする。
- 自分の `q`（状態・`cm`）…`Q` の中に単独で描かれたテキストオブジェクトは、その `q` ブロックを1つの項目とする（元に戻す編集で、描き直した行を1つの範囲として動かす）。

### 2.4 提案・承認・保存

- 提案の `evidence.chain` の要素に `separated` を加えた：テキストオブジェクトの範囲、取り出す演算子と残る演算子の数、取り出すバイト列の sha256、文字、範囲、描き直す場所（`before`・`after`・`within`）。範囲が複数なら `ranges`。
- 承認は PR #104 と同じく要素の id（`chain=[ids]`、CLI `--chain`）。`acknowledge_inference` や装飾の承認では動かない。一部の承認は拒否する。
- 保存前の検査（厳密な監査）は緩めていない。動かした字形・描画の正確な平行移動と、ほかのすべての不変を分けて確かめる。
- 保存記録の `chain_moved` に、分離した数 `separated` を加えた。行は PR #102 の `/PieceInfo` の `moved` に記録し、保存したPDFだけから元に戻せる。

## 6. 固定の後に分かったこと

### 6.1 G4（空の marked content）

固定時は、テキストオブジェクトの中の marked content をすべて拒否する予定で、G4（見出しと行の間の空の `BMC EMC`）を拒否の例とした。実PDF（477 p8）では、InDesign がタブを空白で描く ActualText の span をテキストオブジェクトの中に置く。この span は行の外か行だけを囲むので、MCID がなく、取り出す演算子を囲まないか、それだけを囲むなら扱うことにした（2.2）。G4 の空の `BMC EMC` は行を囲まないので、分離できる。期待と結果の違いとして記録する。行とほかの文字を両方囲む span と MCID は、テストで拒否を確かめた。

### 6.2 PR #104 の連鎖の評価の後退と修正

`23e27ee` で PR #104 の連鎖の評価を再実行すると、追加ケース S1（issue17730 p1）の元に戻す編集が後退した。

- 長文化：分離で、3行目と同じテキストオブジェクトの見出しを取り出さずに残せるようになり、動かす要素が5から3に減った（届く行だけを動かす。PR #104 の規則どおり）。
- 元に戻す編集：段落が短くなるときの規則（動くものの下端から |Δ| 以内の行）が、動かしていない見出しとその下の2行にも届き、それらも上へ動かした。
- **修正（`dd3ea7e`）**：ページの `/PieceInfo` に、前の編集が動かした行の記録（PR #102）があるとき、短くなる編集は記録された行だけを候補にし、記録にない行で止める。記録がないときは従来どおり。テストを加えた。
- 修正後、S1 は字形・描画・画素が元と同一に戻った。リンクの比較は 5.2 の注と同じ理由で不合格と出る（6件とも 0.001 pt 以内で同一）。

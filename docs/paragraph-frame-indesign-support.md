## 1. 拒否の原因の調査

`non-axis-aligned source text matrix unsupported` の原因は、B2の段落認定（`qualify`）が、テキスト行列とCTMの両方が単位行列であることを求めていたことにある。

InDesignは、文字の大きさを `Tf` の値ではなく行列で指定する。`1 Tf` に `Tm 9.567 0 0 9.567` を組み合わせる。フォントサイズ・文字幅・字間（Tc）・語間（Tw）・ベースライン位置（Ts）は、PDFの中ではテキスト空間の値で、テキスト行列とCTMを掛けてはじめてページ上の値になる。B2は、これらをページ上の値として扱っていた。

調べた実PDFでの、文字描画の方式は次のとおり。

| 生成元 | 文字描画 | main |
|---|---|---|
| Word、LibreOffice | `12 Tf`、単位行列 | 編集可 |
| InDesign（府政だより） | `1 Tf` ＋ `Tm 9.567 0 0 9.567`。ページヘッダはForm内 | 全段落を拒否 |
| Quartz（tracemonkeyの図、issue7014） | `1 Tf` ＋ `Tm 12 0 0 -12` ＋ `cm 0.431 0 0 -0.431`（反転が打ち消し合う）。図はForm | 拒否 |
| Antenna House（issue17730）、Ghostscript（canvas） | CTMの拡大 ＋ テキスト行列の拡大。`cm 1 0 0 -1` による上下反転 | 拒否 |

府政だよりの本文の大部分は、ページの内容ストリームに直接描かれていた。Form XObject内にあるのは、各ページのヘッダ（ページ番号と日付）と、p4の地図のラベルである。

PR #89では「Form内の文字が多い」と報告したが、これは誤りだった。`invocation` が空のタプル（ページの直接描画）であるものまで、Form内として数えていた。

## 2. 文字座標変換への共通対応（`text_space.py`）

- テキスト行列とCTMを掛けた線形部分が、次の条件を満たす場合を受け付ける。
  - 回転・せん断がない（b=c=0）。
  - 横方向・縦方向の拡大率 sx・sy がともに正。
- この条件を満たすとき、同じグリフを、単位行列のもとで次の値で描ける。
  - サイズ ＝ size×sy
  - 水平スケール ＝ Tz×sx/sy
  - 字間 ＝ Tc×sy
  - 語間 ＝ Tw×sy
  - ベースライン位置 ＝ Ts×sy
- B2のすべての計測で、このページ上の値を使う。対象は次のとおり。
  - 文字幅
  - 書体の同一性（保存条件 `/PieceInfo` の行の書体、段組の流れでの書体の比較、提案に表示する書体）
  - 新しく描く文字のサイズ
- そのため、`1 Tf`＋`Tm 9.567` と `9.567 Tf` は同じ書体として扱われる。
- 回転・せん断・反転（打ち消し合わないもの）は拒否する。理由として「rotated or sheared」または「mirrored」を表示する。
- 新しい文字は、挿入位置のCTMの逆行列（`q <逆行列> cm … Q`）で既定の座標系に戻してから描く。この方式は、元の文字が描かれていたストリーム（ページまたはForm）のどちらでも使える。
- 特定のPDF向けの分岐はない。行列の条件だけで判定する。

## 3. Form XObject（`form_write.py`）

- **描画元の特定**：編集する文字を描くストリームと、そのFormの呼び出し経路（`invocation`）がすべて同じ場合だけ編集する。ページとFormにまたがる段落や、複数の呼び出しにまたがる段落は拒否する。
- **コピーオンライト**：
  - 文字を描くFormと、そこへ至る経路上のすべてのFormを複製する。
  - 呼び出し元のストリームでは、該当する `Do` 演算子1つだけの名前を、複製を指す名前に替える。
  - 元のFormオブジェクトは書き換えない。同じFormのほかの呼び出し、ほかのページ、入れ子の外側は、元のFormを参照したままになる。
  - 新しく使うフォントは、複製したFormのリソースに加える。
- **公開前の検査**：保存前に次を確かめる。
  - ほかのページの内容ストリームと、そこから参照されるForm
  - 編集したページにあった元のForm

  いずれかが変わっていれば公開しない。
- **挿入位置**：元の文字と同じストリームの中で、次の条件を満たす位置に挿入する。
  - パスの途中ではない。テキストオブジェクトの途中は、§5の条件を満たす位置（編集した最初の文字描画演算子の直前）だけを使う。
  - CTMは回転のない拡大・縮小・平行移動に限る（逆行列で既定の座標系に戻せる）。

  その位置で有効なクリップとForm BBoxが、承認した枠を含むことを確かめる。
- `content_stream.py` は、ページだけでなく各Formの呼び出しごとにも、演算子の境界と描画状態を記録するようにした（`stream_boundaries`）。既存の `boundaries` は変えていない。
- **対象外**：MCIDを持つマーク付きコンテンツがForm内にある場合（タグ付きFormの意味構造）は拒否する。
- **再編集**：複製したFormの文字を再び編集すると、その複製をさらに複製する（T-form-reedit：`/Im1PF` → `/Im1PFPF`）。前の複製は、どこからも描かれないままリソースに残る。複製を参照する呼び出しが1つだけなら、その場で書き換えてよいはずだが、今回は常に複製する安全な側にとどめた。

- **保存の段階での拒否（12件）**：変更しない文字列でも、再組版した文字が推定した枠からはみ出す（capacity、8件）か、保護した画像に重なる（4件）。府政だよりの電話番号の行や、画像の横で折り返す段落である。B2の推定した枠と行の組み方が、元の組版を再現できない場合で、公開せずに拒否している。

- **MuPDFの抽出順（2件、issue7014）**：著者名の右肩の記号（⇤、ベースラインより3.96 pt上）が、B2の行のまとまり（0.35 em以内）に入らず、別の行として扱われる。保存後の内容の順序では記号が名前の後にまとめて並び、MuPDFの抽出順が変わる。描画位置とPopplerの抽出は元と同じである。

評価手順の追加（manifest固定後）：保存サンプルの監査に「変更しない文字列の位置がすべて元と同じ」（文字と原点、0.1 pt単位）を加えた。抽出の比較は空白を無視するため、語間が詰まる誤りを見逃していたためである。この検査は固定した基準より厳しく、結果を良く見せる変更ではない。

## 5. 共通処理として加えた改善

実PDFの監査で見つかった問題を、特定のPDF向けの分岐ではなく一般の規則として直した。

- **約物詰め**：
  - 句読点・閉じ括弧の後ろのアキだけでなく、開き括弧・中点（「（・：；」など）の前のアキの詰めも、観測した送り幅として採用する。
  - 書体が切り替わる位置でも採用する。
  - 詰めの下限は0.2 emとした。InDesignでは「、」が0.43 em、「6（」が0.24 emだった。
- **送り幅（TJ調整）**：観測した送り幅を、書体の切り替えをまたいでも採用する。
- **行のまとまり**：混在サイズを上下中央にそろえた行（ベースラインの差が0.35 em以内）を1行として扱う。各グリフは、行のベースラインからの観測したずれを保つ。
- **段落の区切り**：前の行と書体・塗りの組み合わせを1つも共有しない行（色付きの帯の上の白い文字など）は、段落の続きにしない。
- **行の開始位置**：行頭の空白グリフを取り除いた場合、行の開始位置を最初に残る文字に合わせる。
- **線で囲まれた枠**：全行を囲む線だけの枠（中が塗られていない四角形）は、段落の容器として扱う。新しい文字は、枠の内側に収める。
- **マーク付きコンテンツの容器**：MCIDを持たない、構造に属さないマーク付きコンテンツ（InDesignの `/PlacedPDF`、`/OC` のレイヤー）は、容器として扱う。
  - BDC/EMCは残し、新しい文字はその内側に挿入する。
  - 段落が容器の境界をまたぐ場合と、ActualText付きの `/Span` は拒否する。
- **名前付きの色空間**：`cs` で選んだ色空間と `sc`/`scn` の色を、記録してそのまま描き直す。パターン色は拒否する。
- **挿入位置の描画状態（ExtGState）**：通常の不透明な塗りの見え方を変えない設定だけを受け付ける。
  - 受け付ける：ブレンドモードが通常、ソフトマスクなし、塗りの不透明度が1、オーバープリントの設定のみ。
  - 拒否する：ソフトマスク、透明、ブレンドモードの変更、転送関数。
- **CFFフォントの文字の再利用**：前の編集で消えた文字を、埋め込まれたフォントから見つけ直す（PR #88の仕組み）。InDesignのCFF CIDフォントでは、次の条件で確かめる。
  - ToUnicodeの逆引きで、文字コードがただ1つに決まる。
  - CFFのcharsetに、そのCIDのグリフがある。
  - グリフに輪郭がある。
  - `/W`（`/DW` を含む）がプログラムの文字幅と一致する。

  府政だよりで元の文字に戻す再編集（F-same-reedit）は、これで可能になった。
- **挿入位置（内容の順序を保つ）**：1つの `BT … ET` で複数の段落が描かれていると、従来の挿入位置（テキストオブジェクトの前）では、新しい文字がほかの段落より前に描かれ、MuPDFの抽出順が変わっていた。挿入位置は次の順で選ぶ。
  1. 編集した文字の前の位置。間にほかの文字の描画がない場合。
  2. テキストオブジェクトの後ろ。編集した文字からテキストオブジェクトの終わりまでに、文字以外の描画とほかの文字がない場合（Antenna Houseの見出しと本文）。編集した最初の演算子が、編集範囲より前の文字（行頭の空白など）を残す場合は、1より先にこちらを使う。
  3. テキストオブジェクトの途中。編集した最初の文字描画演算子の直前で `ET` し、新しい文字を描いてから `BT` と、その位置のテキスト行列を設定する `Tm` で再開する（InDesignやpdfTeXが段の全体を1つの `BT` で描き、行を相対移動 `Td` で送る場合）。
     - その位置でテキスト行列と行列（line matrix）が一致する場合だけ使う。`Tm` は両方を同じ値にするため、後続の `Td`/`T*` による位置は変わらない。
     - 再開の方法：テキストオブジェクトの先頭（または最後の絶対位置 `Tm`）からその位置までの位置指定演算子（`Tm`、`Td`、`TD`、`T*`、`TL`）をそのまま繰り返す。後続の行の位置は、MuPDFでは単精度、Popplerでは倍精度で積み上げられるため、行列の値を1つ書くだけでは両方を同時に一致させられない。同じ演算を繰り返せば、どちらの描画エンジンでも元と同じ値になる。行を送りながら文字を描く演算子（`'`、`"`）が間にある場合は、行列の値を書く（倍精度の値がMuPDFの単精度の値と一致する成分は倍精度の値、それ以外はMuPDFの値）。
     - テキストオブジェクト内でクリップ用の描画モード（Tr 4〜7）を使った後や、内部でマーク付きコンテンツが開いている位置は使わない。
  4. 上のどれも使えない場合は、1の位置（間にほかの文字があってもよい）に挿入する。

- **新しい文字の書き方（抽出順と語のまとまり）**：
  - 元のフォントで描く連続した文字は、1つの `TJ` にまとめ、レイアウトしたペン位置との差をカーニング値で表す（元のPDFと同じ形）。1文字ごとに `Tm` を置く書き方では、Popplerが「06（6910）8001」を3語に分けていた。
  - カーニング値は1/100,000 emに丸める。描画位置の計算誤差による微小な値（0.0007など）を、Popplerが語の区切りとして扱うためである。丸め誤差が積み重ならないよう、ペン位置は書いた値から計算し直す。
  - 位置が元の文字の座標そのもの（行の始まり、ベースライン）である場合は、MuPDFが返す単精度の座標ではなく、元のPDFの演算から求めた正確な値を書く。ベースラインが8×10⁻⁶ pt違うだけで、Popplerは同じ高さの2行の順序を入れ替えていた。
- **字間（Tc）を打ち消すTJ調整**：InDesignは、字間 `Tc` を負にし、`TJ` の調整値でそれを打ち消すことがある。文字の送り幅（Tcを含む）と実際のペンの移動が0.25 em以上違い、観測した送り幅が採用されていなかった。その結果、再組版で文字が2.5 ptずつ詰まって重なっていた（府政だより p7「10円きざみ」）。ペンの移動が、Tcを含む送り幅とグリフの幅のどちらかに近ければ、観測値を採用する。
- **空白の幅**：両端揃えでない段落では、空白のグリフも観測した送り幅を保つ。Wordは空白をグリフの幅より広く置くことがあり、再組版で行の残りが4.2 pt左へずれていた（word_osaka_guideline）。両端揃えの段落では、従来どおり空白を元の幅に戻してから行ごとに伸ばす。
- **公開前の画素比較にPopplerを追加**：許可した枠の外の画素比較を、MuPDFに加えてPopplerでも行う。文字位置の計算方法が描画エンジンごとに違い、一方だけで差が出ることがあるためである。
- **約物の連続**：閉じ括弧類の直後に開き括弧類が続く場合（「）【」）は、両方の半角分のアキを詰めて送り幅0まで許す。InDesignは2つを1つの全角枠に収めていた。この送り幅は次の文字に依存するため、閉じ括弧自体の幅の観測値としては使わない。
- **位置の移動だけで表した語間・字間**：空白のグリフがなく、`TJ` の位置調整などで作られた行内の空き（TeXの語間、Word・LibreOfficeの和欧間のアキ、箇条書きの記号の後のタブ）を、直前の文字の送り幅として保つ。段落の行末では捨て、置き換えた文字列の直後にあった空きは置き換え後の文字列の直後に移す。main は再組版でこの空きを詰めていた（tracemonkey で「University of California」が「UniversityofCalifornia」、lo_migration_ja で「LibreOfficeは」の和欧間が詰まる）。監査の抽出比較は空白を無視するため、この誤りは検出されていなかった。保存サンプルの目視確認で見つけ、サンプル監査に「変更しない文字列の位置がすべて元と同じ」検査を加えた。

## 7. 残る障壁と次の技術判断

障壁の種類ごとに、次に必要な対応を挙げる。

1. **マーク付きコンテンツ**（135段落。主に 160F-2019・issue14297 のタグ付きPDFと府政だより）
   - 「入れ子・混在したスコープ」と「ParentTreeに結び付かないMCID（unbound）」が多い。
   - タグ付きPDFでは、1行の中に複数のスコープがある場合や、スコープが段落と1対1でない場合を扱う、意味構造の付け替えが必要になる。
   - 府政だよりでは、`/Span /ActualText` で置き換え文字列を持つ見出しと、`/PlacedPDF` の境界をまたぐ段落が残る。
2. **文字エンコード・グリフの由来**（84段落）
   - 合字・ToUnicodeなしの文字は、これまでと同じ障壁である。
   - 同じ位置に同じ文字を重ね描きする「疑似太字」では、描画元を一意に決められない（ambiguous provenance）。
   - TeXのように語間の空白をグリフとして描かないPDFもある。行の折り返しで生じる空白をフォントで描けないものは、「implicit line-join space has no glyph」として拒否している。
   - 行の中の語間・字間を位置の移動だけで表す段落（TeX）は、空きを直前の文字の送り幅として保つようにした。ただし、TeXの段落テキストには空白がないため、語をまたぐ選択文字列は見つからない（Q-ligature）。
   - 次の段階は、空白を位置の移動として表す入出力方式と、重ね描きを1つの描画として扱う方法である。
3. **描画状態**（43段落）
   - 塗りのない文字（描画モードが塗り以外）、透明な文字、パターン色の文字である。
   - 府政だよりの白抜き文字（塗り＋線）もここに入る。
4. **回転文字**（12段落）
   - 縦書き・回転ラベルである。行の向きの推定と、回転した座標系での組版が必要になる。
5. **Form XObject**
   - 今回、タグのないFormについては、ページ内・入れ子・共有の編集ができるようになった。
   - タグ付きFormの意味構造（FormのStructParents）は対象外である。
   - 複数の呼び出しにまたがる段落（同じFormを繰り返し使う表など）も対象外である。

既存のアーキテクチャ（ストリーム上の演算子を書き換え、公開前に監査する）は、今回の範囲では障壁にならなかった。行列とForm呼び出しの扱いを、演算子ではなく「描画元（ストリームと呼び出し経路）」と「ページ上の値」に統一したことで、例外を積み重ねずに済んだ。

マーク付きコンテンツとタグの付け替えは、ストリームの書き換えとは別の層（構造ツリーの編集）として設計するのがよい。

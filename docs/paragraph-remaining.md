## 2. 方式

### 2.1 段の横に立つ描画（`decoration.side_of_column`）

連鎖の行（`chain`）で、次の行の帯にある描画が、次のすべてを満たすときは、その行の内容ではないとする。

- 横方向に、編集した段落の文字の範囲と、その行の文字・配置物の範囲の両方から 0.5 pt より離れている（文字にかからない）。
- 上端が段落の下端より上（段落の横に立っている）。
- 下端がその行の1行目の下端まで届く（行の横を通り過ぎる）。

これは、スクリーンショット・写真・枠・段の罫線の形。行の一部である印（行頭の●、吹き出しのしっぽ、行の横の小さな印）は、段落の横にない・行の1行目まで届かないので、従来どおり行の内容とみなして拒否する。

- 段の横の描画は動かない。動く行がその描画に当たるかは、従来どおり確かめる（当たれば拒否）。
- 連鎖以外（行の装飾の候補）では変えていない。
- 承認・監査・記録は既存の連鎖のもの（要素ごとの ID の承認、承認変更監査の移動の照合、保存記録と再open）。新しい変更の種類はない。

### 2.2 新しい文字の挿入位置（`auto_writer`）

- 新しい文字は、動かす単位の演算子の範囲の中に書かない（書けば一緒に動く）。従来は、選んだ挿入位置がその中にあると拒否していた（R14）。
- 挿入位置の候補から、動かす単位の中にあるものを除く。従来の拒否の確認は残す。

### 2.3 監査の測定誤りの修正（配置）

- Issue #116 で加えた配置の確認は、出力の字形の原点を提案の基線と比べていた。InDesign の文書では、提案が読む基線と、字形の原点が 0.2 pt 違う（R14：基線 873.877、原点 874.077）。出力は元と同じ位置に描かれているのに、不合格になっていた。
- 元の文書がその行を描く位置（原点）と、提案の基線との差を測り、出力も同じ読み方で比べるようにした（`drawn_offset`）。
- これまでの評価の出力25件（パネル・クリップ・スモーク・R ケース）で確かめた：変わったのは R14 の2手だけ（不合格→合格、差 0.2 pt）。他はすべて差 0 で結果は同じ。

## 6. 判断事項

1. **段の横の描画の判定の範囲**
   - 「段落の下端より上から、次の行の1行目の下まで届き、文字から 0.5 pt より離れている」描画を、段の横に立つものとした。
   - R15・R16 の、行の上の小さな印・短い縦の帯（段の装飾かもしれない）は、行の内容とみなして拒否のまま。帯が段落とともに伸びるべきかは、別の変更の種類。
   - 代替案：段の装飾（縦の帯）も一緒に伸ばす変更の種類を設ける（設計判断）。
2. **R03 の元に戻す編集**
   - Poppler の画素1行が、動かす行の範囲（±1 pt）の外で違う。字形のアンチエイリアスが箱より上に出るため。
   - 範囲を広げるのは既存の安全な検査を緩めることになるので、変えていない。代替案：動かす行の範囲を、描画の実際の範囲（レンダラーで測る）にする。
3. **検索・抽出の不合格**
   - R03（元の文書の隙間）・R14（Poppler の切り抜き）は Issue #116 の方針どおり不合格のまま。
   - R04 は、評価のケースの置換が行頭の「•」を含むため。利用者の編集としては「•」を除いた選択が自然。ケースの定義は変えていない。
4. **配置の確認の限界**（R13、今回の変更とは無関係）
   - 1行の中で欧文と和文の字形の原点が 0.3 pt 違う（フォントごとの基線の差）。行を2つに分けて読み、左端の確認が不合格になる。R13 の実用成功が不合格のまま。
   - 代替案：同じ行の字形を 1 pt 以内でまとめて読む（測定の修正）。
5. **型 B（背景の出入り、9件）**：角の丸い背景・入れ子の背景の変形が必要。今回の承認の範囲を超えるので、設計判断に回す。
6. 実用成功の新規は 0件。今回の変更で保存できる範囲は広がったが、3件とも検索・抽出は元の文書の性質で不合格になる。

# 旧文字除去だけを切り出した実PDF診断

これは編集成功率に含めない診断である。凍結した評価前 backend の `replace_region` に空の `LayoutResult` を渡し、既存の削除操作と整合性監査を実行した。通常編集の `validate_editable` / `validate_collisions` を変更していない。通常なら編集拒否されるページも、削除プリミティブ自体の境界を調べるためメモリ上のコピーで観察した。診断PDFは保存していない。例外後のPNGも安全な編集結果を意味しない。

再現: `.venv/Scripts/python.exe -m evaluations.realpdf.diagnostics.removal_visual_audit`

エンジン: `evaluations/realpdf/baseline/pdfeditor/backend.py`、SHA-256 `3dba3a3424c090aab1c69315b71bbc5d35764d909b2a0f93df078ae8038d157e`、PyMuPDF 1.27.2.3。各PDF原本のハッシュが不変であることも記録した。

## 削除操作と、その保証範囲

各選択Glyph bboxの中央に0.1pt角のredaction領域を置き、`add_redact_annot(fill=False, cross_out=False)`、続いて `apply_redactions(images=0, graphics=0, text=0)` を実行する。描画で隠す処理ではなく、PDFの文字描画を除去する処理である。`fill=False` なので白い矩形を塗らない。削除後に `get_texttrace` 由来の全Glyphを再取得し、非選択Glyphの「文字・原点を小数2桁に丸めた値」のCounterと比較する。独立した文字抽出 `page.get_text()` も結果JSONに保存した。

STidの目視では黄色背景、黒枠、赤い下線が残り、その上の赤い文字だけが消えた。したがって文字に付随する下線が別vectorなら、文字を消しても下線は残る。文字装飾までまとめて再編集する機能を意味しない。Canvia p1-b7では選択したa./b.項目だけが消え、b.の折返しが別Boxに残った。削除操作が推定された選択範囲どおりでも、TextBox推定自体が文章単位を誤れば不自然な編集範囲になる。

fill-only診断は、同じbboxに重なる文字描画を区別できないことを実PDFで示す。見た目だけでは32文字を選んだつもりでも、位置に基づくredactionは同位置のstroke描画も巻き込む。現行監査はその結果を拒否した。通常編集ではこの見出しは非fill描画の事前ガードでも拒否される。任意の重なりを個別に編集するにはcontent streamの描画オペレータ単位で選択・置換するbackendが必要であり、幅推定の改善だけでは解決しない。

## 無関係vectorの数値差分

STidで0.001ptに丸めたdrawing fingerprintは一致したが、厳密比較では362個の数値要素に差があり、最大値は0.000030517578125ptだった。変更画素は黄色枠の上辺、左下隅、寸法矢印の下側先端に現れた。bbox外440画素のうち414画素、2pt余白外42画素のうち16画素が、最大チャンネル差8/255を超える。最大差は16/255。目視では形状の欠損は見られないが、「編集領域外のピクセルが完全不変」とは判定できない。

content streamの再書込みで生じた微小な座標差とラスタライズ境界の変化に整合する観測である。内部の数値丸め経路までは断定しない。検証を粗いgeometryハッシュだけで済ませると、この差分を見落とす。

## 新潟の安全側拒否は丸め境界に敏感

例: 非選択文字「を」のy座標は594.5250244140625ptから594.52490234375ptへ変わった。差は約0.000122ptだが、小数2桁に丸めると594.53と594.52になり不一致となる。全1053Glyphが同一Unicode・同一個数で一対一に近傍対応し、最大bbox差も0.000122pt、フォント・サイズ・paint種別も一致した。対象外領域の144dpi画素差は0だった。

この個別結果は「隣接文字を削除した」という証拠ではなく、現行の丸めCounter監査による過剰拒否である。診断用の近傍対応は原因確認のためだけに使用し、実編集の監査を緩めていない。将来許容差を導入する場合も、Unicode、個数、重複描画、座標の一対一対応を同時に検証する必要がある。

詳細は `results.json` と各ディレクトリの `result.json`。各 `comparison-crop.png` は原本と削除のみの並列比較。PNGを目視確認し、失敗状態も診断証拠として残した。
